## 直接对应的岗位要求

岗位要求第 3 条：

> 熟悉 Kubernetes 和容器化技术，具备在集群环境下进行开发、部署、排障或性能优化的经验；

相关职责还包括：任务执行等组件的封装与接入验证，解决并发、资源、链路和行为一致性问题，以及重视测试、日志、性能和稳定性。目录围绕这些能力组织，训练内部知识继续复用既有 Slime 与强化学习学习记录。

## 八类目录怎样服务这个目标

| 目录 | 对岗位有用的学习目标 | 当前控制的深度 |
| --- | --- | --- |
| `00-overview` | 连贯解释一个任务怎样提交、调度、运行并反馈状态 | 先走通一条正常 Job 主线 |
| `01-architecture` | 将运行或失败现象定位到责任组件 | 理解 API Server、控制器、Scheduler、kubelet、运行时的分工，不预设通读其源码 |
| `02-resource-model` | 能读写对象、筛选目标并理解状态变化 | metadata/spec/status、Namespace、Labels 与实际需要的对象关联 |
| `03-workloads` | 把任务落实为合适的执行对象 | 当前以 Pod/Job 为主，其他类型遇到实际需求再补 |
| `04-runtime-environment` | 配置并排查计算资源、网络、存储与运行参数 | 能说明工作需要什么、配置怎样影响执行；不扩展为所有基础设施实现 |
| `05-security-and-isolation` | 说明执行边界，使用必要权限与隔离配置 | 先理解和应用；沙箱运行时内部实现按问题选读，JD 不要求自研安全运行时 |
| `06-operations` | 用证据定位问题并验证修复 | 结合一个真实的小任务保留可复现的部署或排障过程 |
| `90-clients` | 使用命令行或 Python 接入资源操作 | kubectl 与当前 kr8s 调用；沿已有 Python/异步基础学习，不重开整套语言课 |

## 当前先做什么

先补清整体主线、资源的期望/观察模型和协调循环，再把当前 Job 查询、创建与状态交接接回这张图。通用知识正文保持在 `k8s/`，Agent Lightning 的 Gateway、变量与自定义控制器留在函数卡及项目参考。

进入实践时，优先围绕同一个最小工作负载积累证据：提交与观察一次执行，再对一种实际遇到的配置或运行问题作定位、修复和复查。资源、网络、日志和权限等方向由真实现象决定，不为了填满目录逐项制造任务。

“能部署一个小任务，并解释一次问题如何被定位和修复”是本学习计划建议的检查点，不是招聘方承诺的录用标准。源码阅读、写出材料和真实集群经验分别记录；这个目录支撑岗位的 Kubernetes 部分，不代表整个岗位能力已经满足。
