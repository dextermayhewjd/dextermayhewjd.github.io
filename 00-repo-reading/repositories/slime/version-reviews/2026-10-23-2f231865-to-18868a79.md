## 2. Step 0 的主线还成立，入口和一条数据交接需要更新

新版公开入口仍是 `generate`，但主要业务编排已移到同文件的 `_generate`。`generate` 外层组织 trace 与导出；依照原有剪枝方法，应越过这层包装，进入实际串联业务的 `_generate`。

下面是新版正常训练路径的教学裁剪；省略 trace、检查、异常、参数细节及最终清理。它是迁移对照，没有覆盖原 Step 0。

```python
# generate(...) 调用 _generate(...)；下面展开 _generate 的主要业务
state = _AdapterService(...)
agent_name = agent_name_for(...)
harness = _AGENTS[agent_name][0]()
adapter, adapter_url, _ = state.endpoint(agent_name)

adapter.open_session(...)                              # 1. 登记会话
async with boot_agent_sandbox(..., harness=harness) as sb:  # 2. 准备沙箱与 CLI
    baseline = await swe.prepare_workspace(...)         # 3. 准备工作区，并保存初始 Git 树
    agent_exit_code = await harness.run(...)             # 4. 运行 CLI；请求处理发生在等待期间
    agent_metrics = await harness.collect_metrics(...) # 新增：沙箱回收前取得 CLI 统计
    diff_text = await swe.git_diff(sb, ..., baseline)     # 5. 相对初始树提取本次改动

reward, applied_cleanly = await swe.run_evaluation(...) # 6. 独立评测
samples = await adapter.finish_session(...)             # 7. 导出训练样本
...  # 结果元数据、截断状态与最终清理
return samples
```

最值得先修正的两点：**指挥官位置由 `generate` 的函数体移到 `_generate`；`prepare_workspace → baseline → git_diff` 成为显式交接。** 原来的七个业务环节并未消失。[新版源码](https://github.com/THUDM/slime/blob/18868a79b0b083a093798a94ed0f8cb4f71b9c14/examples/coding_agent_rl/generate.py#L225-L367)

## 3. 对已有各步的影响

| 旧步骤 | 仍成立的认识 | 新版需要校准或补读的内容 |
| --- | --- | --- |
| [Step 0：核心骨架](../steps/step-000-coding-agent/01-scope.md) | 一份任务沿会话、环境、执行、评测、样本导出推进 | 公共 `generate → _generate`；每份 sample 可以选择 agent；工作区基线和 CLI 统计增加交接 |
| [Step 1：单轮模型请求](../steps/step-001-harness-to-adapter/01-scope.md) | 转换、编码、生成、解析、回复与轨迹记录的职责仍在 | `_run_turn` 改用 `_session_prompt_ids`；在可验证匹配时复用历史原始 token，保留普通模板渲染回退；`partial_rollout` 开启时，`call_sglang_generate` 可续接被中断的多次请求，不能再概括为必定一次 POST；Anthropic 工具结果会按调用顺序重排 |
| [Step 2：评测](../steps/step-003-swe-evaluation/01-scope.md) | 在新的独立环境应用补丁、执行评测，返回 reward 与 applied_cleanly | 评测环境改经 `_evaluation_sandbox → create_sandbox`；临时文件移到 `/tmp`，补丁策略顺序和长评测命令处理有调整；可指定 `eval_user` |
| [Step 3：轨迹变样本](../steps/step-004-trajectory-to-samples/01-scope.md) | `shutdown_session → finish_session` 收尾与导出、按树叶取得轨迹链的模型仍在 | `TurnRecord` 增加 replay、权重版本和生成统计；`_SampleBuilder` 的拼接、分段与导出扩展；共享前缀保留原 logprob，训练与否仍由 mask 控制。上层函数不变，不表示其下游完全没变 |
| [Step 4：会话与服务准备](../steps/step-005-agent-preparation/01-scope.md) | sid 标识一次执行，`store[sid]` 保存会话状态 | 服务引入 `endpoint(agent_name)` 缓存不同 agent 的 Adapter/监听入口；Session 增加模板参数、历史 prompt 前缀和 trace；`_session_id` 函数本体未变 |
| [Step 5：沙箱启动](../steps/step-006-agent-sandbox/01-scope.md) | 创建本地对象、进入远端环境、安装 CLI、交付与回收的生命周期仍在 | `E2BSandbox(image)` 改为 `create_sandbox(image)`；默认 provider 是 `sunabako`，显式 `SWE_SANDBOX_PROVIDER=e2b` 仍可选择原实现；Claude 安装增加 native 包分支，npm 路径保留 |
| [Step 6：工作区准备](../steps/step-007-prepare-workspace/01-scope.md) | 用户/目录、前置命令、题目文件准备仍在 | `prepare_workspace` 从无返回值变成返回初始 Git tree；`git_diff` 需要这个 baseline，避免将镜像原有改动误算为本次 Agent 改动 |
| [Step 7：Harness 启动与等待](../steps/step-008-harness-communication/01-scope.md) | `BaseHarness.run` 的四个直接部分、`run_agent` 委派执行、退出码逐层返回仍在 | Claude 配置增加压缩钩子，启动命令增加 CLI pid/压缩状态；`_await_done_marker` 从 `sb.exec(test/cat)` 改为 `sb.read_file` 轮询。旧图的这个叶子节点需要校准 |
| [Step 8：HTTP 接收](../steps/step-009-adapter-request-entry/01-scope.md) | Claude/Anthropic 的 `POST /v1/messages → _run_turn`，以及 app、路由、监听、Request/body 的关系仍适用 | 监听启动位置由服务初始化的直接代码移进 `endpoint()`；`_run_turn` 起始行改为 387。Codex 默认配对改为 `ResponsesAdapter` 的 `/v1/responses`，不能继续把旧 Chat Completions 路径当作当前 Codex 入口 |

另一个对 Coding RL 有意义的新增分支：远端环境发生 `SandboxTerminatedError` 时，新版尝试把已经生成的轨迹以零奖励导出；这与一般异常直接返回 abort 结果不同。它适合后续作为“失败如何成为训练数据”的具体问题补读，不必在第一次校准正常路径时全部展开。

旧版“记录生成 token 的 logprob”的结论仍是基础，但新版还能按配置携带 top-p/top-k 或路由 replay 等数据。不能把新增字段说成每次必有，也不能把旧卡的字段列表当作新版完整合同。

## 5. 建议怎样继续，而不重读全部步骤

1. **先校准 Step 0 的新版地图。** 用第 2 节的小骨架对照已知职责，确认入口、baseline 与新增统计；保留原 Step 0 的固定版本。
2. **接续当前 Step 7/8 的最小差异。** 在读新版时认清 `endpoint()` 和标记轮询的改动，然后继续原来的 HTTP 接收问题；Anthropic 路由仍可作为首个观察点。
3. **把真正新增的 RL 机制拆成后续问题。** 优先考虑 Step 1 的原始 token 前缀与 partial rollout、Step 3 的 replay/权重版本。它们值得独立理解，不挤进一次版本校准。
4. **旧卡按需迁移。** 保留旧 `02`/`03` 的源码版本、原话与未知；当前真正要用的卡片调入本步 `02` 后，核对并增加新版差异，再按既有规则继承。复制、改行号、补助手说明不算用户新增理解。

若当前只想把旧版链路读完，也可以继续绑定 `2f231865`，通过固定提交查看源码；应避免一边看新版文件、一边将旧版卡片当成当前事实。本次没有替用户决定后续全部迁移到哪个版本，也没有覆盖各步 scope 或函数记录。
