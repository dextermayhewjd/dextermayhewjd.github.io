# Dressage 原测试对 Harbor 升级覆盖到哪里

**基线是 Dressage `3e3142f`。** 本页统计它自带的 `tests/integrations/harbor`。升级笔记的回归脚本单列为后来取得的证据。0.18.0 是原支持版，0.26.0 是本次目标。

## 原套件有多少，升级有多大范围？

一个测试函数可以给多种输入，所以 pytest 会收集出更多用例。本次复跑 0.18.0 为 66 通过，0.26.0 为 63 通过、3 失败，两版均排除 8 个需显式启用的端到端用例。专项目录之外还有两处测试文件提到 Harbor，分别用样本数据测试奖励日志、用请求头测试 Proxy 客户端；这两处不计入专项套件分母。[原测试清单](00-version-target/original-suite-collection.txt) · [本次运行记录](00-version-target/original-suite-calls.txt) · [默认选择条件](https://github.com/Accio-Lab/Dressage/blob/3e3142fe8ea07e4504c3b20a936a4c201a3de44c/pyproject.toml#L41-L46) · [奖励日志测试](https://github.com/Accio-Lab/Dressage/blob/3e3142fe8ea07e4504c3b20a936a4c201a3de44c/tests/test_log_rollout_data.py#L56-L79) · [Proxy 客户端测试](https://github.com/Accio-Lab/Dressage/blob/3e3142fe8ea07e4504c3b20a936a4c201a3de44c/tests/test_proxy_client.py#L35-L56)

**升级时要审核 61 项用法。** 固定扫描在 33 个文本文件里归档了 191 个 Harbor 相关位置。六个 Dressage 集成实现文件占 177 处，去掉两处属于 Dressage 内部操作的位置，实际涉及交接的是 **175 处**。其中 171 处位于 **53 个函数或方法**内，另 4 处位于模块顶层。把这些位置与入口配置、示例脚本、Harbor 回调和下游文件一起按用途归类，得到 61 项。一个完整 Trial 可以同时验证多个用法。[191 处的归属](../usage/source-index.md#locations) · [61 项审核入口](../usage/README.md#routes)

## 三个报错以外，原测试漏检了什么？

为查明调用是否跨过 Harbor 和 Dressage，我另选了两端共 16 个实际方法入口，按进入该方法的**不同 pytest 用例数**统计。0.18 和 0.26 在这 16 个入口上得到相同计数。观察范围包含 pytest 主进程的 setup、call、teardown，按源码文件和方法全名识别实现，同一个用例多次进入只计一次。子进程内部另需观测。[观察脚本](00-version-target/observe_original_suite.py) · [两版的 16 个入口计数](00-version-target/original-suite-calls.txt)

| 要验的交接 | 原测试实际到达 | 从原套件还能确定什么 |
| --- | --- | --- |
| 工厂 → Dressage 后端预检 | Harbor 工厂 **0**，直接进 Dressage 预检 **1** | 该用例断言后端构造的 bwrap 命令。0.26 工厂传入 `kwargs` 引起的错误需要从工厂入口单测。[01 的失败输出](01-environment-preflight/factory-contract-results.txt) |
| Trial → 回收非空日志 | Harbor 日志回收 **0**，Dressage 的目录下载 **0** | verifier 夹具能令原套件报错。它不会发现直挂目录复制到自身，也不会验证改绑后文件交付。[02 的两种输入](02-output-mounts/README.md#mount-matrix) · [03 的两项失败](00-version-target/pytest-0.26.0.txt) |
| Harbor 运行、取消 → 插件收尾 | 真实 Trial.run **0**，Trial._emit **0**，Dressage 的取消回调 **1**、结束回调 **5** | 夹具驱动的插件分支有断言。第二轮专项已观察受控 Trial 的事件顺序、提交次数和路由释放。[11](11-trial-events/README.md) |
| Harbor 重试结果 → 训练样本 | 真实 Job.run **0**，队列重试 **0**，Dressage 的 on_job_end **1**、commit_attempt **11**、_bundle_samples **1** | 能验证给定一份结果时 Dressage 怎样处理它。第二轮专项实际触发队列重试，并比对 JobResult、manifest、Sample 的 ID。完整训练入口待验。[13](13-final-attempt/README.md) |

0.26 下原套件的三个失败中，一项停在测试写死的 **0.18.0 版本断言**，另两项停在**同一份独立 verifier 夹具**。对应问题 04 和 03。问题 01、02 和 21 的生产缺陷是从真实 Harbor 调用另行复现的。[原失败名与错误](00-version-target/pytest-0.26.0.txt) · [工厂回归](01-environment-preflight/README.md#evidence) · [日志回收回归](02-output-mounts/README.md#mount-matrix)
