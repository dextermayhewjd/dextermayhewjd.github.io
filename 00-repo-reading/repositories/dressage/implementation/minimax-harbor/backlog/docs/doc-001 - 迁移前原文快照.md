## 模型后端接入：候选判断，尚未形成补丁

原链路：`messages/tools → input_ids → generate_preemptible → SGLangRouterClient.generate`。

| 已核对的源码 | 事实 | 设计含义 |
| --- | --- | --- |
| `server.py:1939` | pipeline 读取 messages/model/tools | 对话消息边界是首要候选 |
| `server.py:2087,2198` | 取 input_ids，委派生成控制器 | 到控制器时已不是原始消息 |
| `generation_controller.py:244,675` | 委派客户端；兼容它支持的参数 | 这里不是通用消息 API 适配器 |
| `sglang_client.py:176,208` | token 参数发往 `/generate` | 不能只换 URL 就当作 MiniMax 已接通 |
| `server.py:2479` | 交互记录依赖 token/logprob/版本等 | 必须一起核对响应与结果记录合同 |
| `server.py:881–883` | 默认路径加载 tokenizer | API 路径需处理初始化依赖，不能随意下载一个 tokenizer 代替 |
| Slime `train.py` | eval-only 判断前已初始化训练模型并同步权重 | “只评测”不自动等于“无 GPU” |

`create_app` 允许注入 sglang_client，但其合同仍是 token 与 SGLangResponse。Gateway 可配置 upstream_origin/headers，但直接转发厂商也不自动满足会话、轨迹与 ArtifactStore 合同。应比较这些接缝后选择修改范围，而不是提前认定必须改控制器。

**2026-11-17 复核补充**：Dressage gitlink 固定 Slime `aaf5c2092b01219fa0d5c2d323741d409086ca32` 且本地未初始化，训练脚本默认使用该子模块。下述独立 Slime checkout 的源码结论不能自动外推到它。Harbor 版本由 compat.py 运行时严格检查，不只是依赖声明。结果层已有 require_trainable_tokens 配置，先验证 rollout 配置能否满足要求再决定修改。

以上 Dressage 行号对应固定提交 `3e3142fe8ea07e4504c3b20a936a4c201a3de44c`；Slime 依据 `18868a79b0b083a093798a94ed0f8cb4f71b9c14`。来源包括 `docs/harbor.md`、Harbor 训练脚本与上述源码；均为静态核对，未执行模型。

## MiniMax：官方接口与待确认配置

2026-11-17 已查官方国际站 [OpenAI 兼容接口](https://platform.minimax.io/docs/api-reference/text-openai-api)与 [Anthropic 兼容接口](https://platform.minimax.io/docs/api-reference/text-anthropic-api)。两者提供消息与工具交互相关能力，但参数支持有差异，多轮交互须保留官方要求的完整助手响应。

当前优先考虑已有 OpenAI 消息边界，属于助手建议，尚未确定最终实现。国内文档对应页面当次抓取超时，不能用国际站地址替用户决定账户地址。尚需模型名、Base URL、首轮可用环境后端；密钥只在运行环境配置，不写入仓库。

## 结果记录：评测与训练资料分清

API 缺少的真实 token ID、logprob、权重版本应明确标记缺失，不能重新分词或补零后声称恢复原训练轨迹。既要让 Agent 收到可用响应，也要让 Harbor 的结果提交和清理完成。

评测说明的是“模型在固定 Agent、工具、提示、题目和环境下的表现”。比较时固定相关条件，保存模型标识、时间和预算，区分模型答错、API 故障、工具失败及沙箱问题。模拟响应只验证工程合同，不提供模型表现证据。

## 预热：属于第二阶段的环境实现

Harbor `Trial._start_agent_environment` 委派 Environment.start；后端可冷创建或热领取。已读 Harbor v0.25.0 的 ACK 后端有 SandboxClaim 分支，但属于 OpenKruise，并非本轮目标 Agent Sandbox 的现成适配，也未验证在 Dressage 依赖的 0.18.0 可用。

Dressage 原生 PrewarmStore 保存 Paddock 会话句柄，Harbor 有自己的 Environment 生命周期；本次未找到原生预取调用接入 Harbor 的路径。因此不能说 Harbor 完全不支持预热，也不需要先搬运原生预热模块。作者未复用它的真实动机未获证实。
