S07.6 有效指导的模式：按问题选择解决方案

7.5 讨论了应该给 Agent 多大自由度。这里继续解决一个实际问题：已经写清要求，执行时仍然出错，应该改哪里？

本章对应官网的 Patterns for effective instructions。六种模式各有独立页面，每页按“问题 → 解决方案 → 最小示例 → 怎样检查”展开。

  • 7.6.1 记录容易踩的坑，纠正常见错误假设
    问题：通用经验在本项目里不成立。解决方案：提前告诉 Agent 具体例外及处理办法。

  • 7.6.2 用模板明确产物应有的结构
    问题：结果看起来完整，关键字段却遗漏。解决方案：提供实际模板，说明各项应填写什么。

  • 7.6.3 用检查清单跟踪多步任务
    问题：多步任务漏做了其中一步。解决方案：将进度与每一步的完成证据对应起来。

  • 7.6.4 验证结果，失败后修正并重试
    问题：做完了，但没有证据证明结果正确。解决方案：用验证结果驱动修正与复查。

  • 7.6.5 执行前先验证计划
    问题：计划本身有错，执行后才发现。解决方案：将计划与真实输入核对，再执行。

  • 7.6.6 把重复操作封装成可复用脚本
    问题：每次都重新写同一段工具代码。解决方案：保留经过检查的代码和稳定调用方式。

这些是可组合的模式，不要求各自都创建一份新 Skill，也不要求每份 Skill 全部采用。

前几个单元使用本站已有的 Git 审查练习作例子；验证循环在临时副本中实际运行；计划验证保留官网的表单例子。每页会注明哪些内容是教学改写、哪些命令和结果来自实际执行。

易错点、模板和清单帮助模型理解、组织任务；验证器检查明确条件；脚本执行固定逻辑。需要强制“检查未通过不得继续”时，还需由宿主程序实现相应的控制。

S07.6.1 记录容易踩的坑，纠正常见错误假设

先读官网关于软删除、用户 ID 字段和健康检查的中文例子，再用 Git 练习将项目例外写成可执行的提醒。

3 分钟

S07.6.2 用模板明确产物应有的结构

先读官网报告模板的中文例子，理解固定结构与待填写内容，再把模板用于代码审查。

3 分钟

S07.6.3 用检查清单跟踪多步任务

从官网表单清单理解步骤跟踪，区分清单指令、任务状态、结果验证与执行约束。

4 分钟

S07.6.4 验证结果，失败后修正并重试

用官网编辑工作流的中文例子，理解修改后验证、失败后修正并复查、通过后再继续。

3 分钟

S07.6.5 执行前先验证计划

把准备执行的计划保存为中间数据，先与真实输入核对，再进行实际操作。

2 分钟

S07.6.6 把重复操作封装成可复用脚本

复用现有 Git 快照脚本，观察输入环境、实际输出和失败返回，区分脚本代码与调用指令。

2 分钟
