把自己的 Agent 接回 slime

要接入自己的 Agent，最小需要提供哪个入口？

默认 rollout 会查看 custom-generate-function-path，动态加载你的异步生成函数。coding_agent_rl 就用这个入口接入；函数接收 args、Sample 和采样参数，可选接收 evaluation。
返回一个 Sample 或多个 Sample，并填好 token、response_length、loss_mask、状态和需要的奖励。已经填 reward 的样本可跳过单样本奖励计算；更换整个任务调度时才考虑 rollout-function-path。
--custom-generate-function-path \
  examples.coding_agent_rl.generate.generate

输入：Sample + sampling_params
输出：Sample 或 list[Sample]

命令参数来自当前样例。到这一课，可以沿着入口把前面各组件的责任串起来。

slime/rollout/sglang_rollout.py · generate_and_rm

            custom_func_path = sample.generate_function_path or args.custom_generate_function_path
            generate_func = load_function(custom_func_path) if custom_func_path is not None else generate

            if custom_func_path is not None and "evaluation" in inspect.signature(generate_func).parameters:
                generate_call = generate_func(args, sample, sampling_params, evaluation=evaluation)
            else:
                generate_call = generate_func(args, sample, sampling_params)

换一种 Agent 策略就必须重写整个 rollout 吗？

展开复述参考通常先替换单样本生成函数，复用 slime 的默认调度。只有任务结构或调度需求超出这个接口时，才换整个 rollout。
更多细节与源码出处

有 group_rm 时，奖励在组级处理；本课提到的跳过规则指默认的逐样本奖励路径。生成结果后还有 sample hooks 和队列上下文继承。

这是默认 rollout 下的接入方式。返回的 sibling samples 应共享 rollout_id；任务自定义配置与实际运行环境仍由配方和任务层负责。
