问题：收到了结果，工作进程就已经退出了吗？#

第 12 讲用 Pool.starmap 收集返回值。本讲把这一层拆开：一个生产者把题目送进队列，一个工作进程生成答案，父进程收集结果。最后还要确认两者退出。随后换成外部命令，观察超时以后谁负责清理。

阅读顺序是：创建进程 → Queue 交接 → 完成消息 → 等待退出 → 超时升级清理。这里不启动模型、Ray 或网络服务；实验只创建自己的短命子进程。

1. 先创建执行边界，再启动工作#

Slime 的 launch_server_process 为模型服务选择 spawn，创建 multiprocessing.Process，调用 start()，然后检查服务健康。在健康检查中，is_alive() 只能回答“进程是否还活着”，不能回答“HTTP 服务已经可用”。

ctx = multiprocessing.get_context("spawn")

process = ctx.Process(
    target=worker_process,
    args=(task_queue, done_queue, query_single_turn, get_rule_based_math_reward, None, {}),
)

Process(...) 先建立进程对象；start() 才安排子进程执行 target(*args)。spawn 会启动新解释器，因而把入口放在 if __name__ == "__main__": 下，worker 放在模块顶层，传递可序列化的参数。子进程不会共享父进程里的普通列表。

这里 multiprocessing.get_context("spawn") 返回具有 Process、Queue、Pool 工厂的上下文，相关对象统一从它创建。源码用 multiprocessing.set_start_method("spawn", force=True) 改全局选择；库式代码通常更适合局部上下文。不要在任意导入位置反复设置全局启动方式，也不要混用不同上下文创建的同步对象。Python 3.12 启动方式

创建者负责清理自己创建的进程。multiprocessing.active_children() 返回当前进程仍活着的 multiprocessing 子进程，不是全系统进程表。Slime 在启动前后取差集记录新路由器；实验只检查已经握有的 worker 是否在其中，不遍历并杀掉其他任务的子进程。

2. 从题目队列走到完成消息#

输入交给 task_queue.put(item)，worker 用 task_queue.get() 取出。计算结束后，把含 messages、reward、instance_id、extra_info 的结果交给 done_queue.put(output_item)。这是真实生成器使用的字段和交接方向。

def worker_process(task_queue, done_queue, rollout_func, reward_func, client, sampling_params):
    for item in iter(task_queue.get, "STOP"):
        messages, finish_reason = rollout_func(client, item["prompt"], sampling_params)
        item["messages"] = messages
        output_item = {
            "messages": messages,
            "reward": reward_func(item),
            "instance_id": item["instance_id"],
            "extra_info": {"finish_reason": finish_reason},
        }
        done_queue.put(output_item)
    done_queue.put("COMPLETE")

这是教学裁剪：保留原 worker_process 的签名、两条 Queue 和 STOP/COMPLETE 协议；只启动一个 worker，固定返回答案 4，删去 HTTP 调用、UUID、采样统计、JSON 字符串输入和结果上报。extra_info 只保留一个字段，真实实现放入更多题目与采样信息。生产者 read_data_into_queue 从原来的局部函数移到模块顶层，显式接收队列，以便用 spawn 导入；真实实现还读文件、打乱数据并重复投递。

def worker_process(task_queue, done_queue, rollout_func, reward_func, client, sampling_params):

    for line in iter(task_queue.get, "STOP"):
        if isinstance(line, str):
            item = json.loads(line)
        else:
            item = line

        # try:
        messages, finish_reason = rollout_func(client, item["prompt"], sampling_params)

        item["uid"] = str(uuid.uuid4())
        item["messages"] = messages
        reward = reward_func(item)
        item["rollout_index"] = 1
        item["reward"] = reward
        item["extra_info"] = {}
        item.update(sampling_params)
        item["timestamp"] = str(time.time())
        item["round_number"] = len([_ for _ in item["messages"] if _["role"] == "assistant"])
        item["finish_reason"] = finish_reason

        output_item = {
            "uid": item.pop("uid"),
            "messages": messages,
            "reward": reward,
            "instance_id": item.pop("instance_id"),
            "extra_info": item,
        }

        done_queue.put(output_item)

    done_queue.put("COMPLETE")

每个 worker 需要自己的停止消息。一个 STOP 只能被一个消费者取走；父进程也要收齐 worker 数量的 COMPLETE，不能因为暂时没收到结果就判断整个生成任务完成。

multiprocessing.Queue.empty() 和 qsize() 只适合诊断，不能拿来决定“接下来 get() 一定不会阻塞”或“所有生产者已经结束”。put() 后还有后台线程把数据送进管道，观察值也会被其他进程立即改变；qsize() 在 macOS 等平台还可能不可用。实验用明确的结束消息，父进程用 done_queue.get(timeout=10) 给异常路径留出口，超时抛出标准库 queue.Empty。Queue 的传输与限制

3. COMPLETE 以后，还要 join#

运行 example.py：

python3 -W error example.py

Python 3.12 输出：

owned worker True
results [(10, 1), (11, 1)]
joined True
join timed out True
process reaped True
pool [4, 9]

前半段先消费结果，再对生产者和 worker 分别 join(timeout=5)。收到 COMPLETE 是业务协议；join 等待的是操作系统进程结束。join(timeout=...) 的返回值不表示成功与否，要再看 is_alive() 和 exitcode。退出后的 Process.close() 释放进程对象的句柄，不能用它代替停止仍活着的进程。

后半段刻意创建一个睡眠 60 秒的进程，join(timeout=0.01) 返回时它仍活着，随后按照 Slime 路由器的顺序处理：

if process.is_alive():
    process.terminate()
    process.join(timeout=5)
if process.is_alive():
    process.kill()
    process.join()

terminate() 在 POSIX 发送 SIGTERM，kill() 在 POSIX 使用 SIGKILL；Windows 的行为不同，不能把它们都理解成可执行 Python 清理逻辑的通知。它们也不自动终止后代进程。源码把等待限制在剩余清理预算内；教学例子只处理自己的单个无后代睡眠进程，因此最后的 join() 不另设置预算。Process 生命周期

4. Pool 替你分派任务，仍需要关闭边界#

现在回到第 12 讲：ctx.Pool(...) 管理多个 worker，pool.starmap(conversion_worker, ...) 分派参数元组并等待返回值。本讲例子把生命周期显式写出：成功后 pool.close() 停止接收新任务；随后 pool.join() 等待 worker 退出；失败时改为 pool.terminate() 放弃尚未完成的工作，再 join()。

真实转换工具使用 with ctx.Pool(num_workers) as pool:。要注意，Pool 的上下文退出调用 terminate()；不是所有上下文管理器都承诺等完未完成工作。此处 starmap 已经同步返回，结果才进入后续权重汇总。如果改成后台提交后立刻离开 with，就不能沿用“所有任务都做完了”的推断。Pool 关闭合同

5. 外部命令超时：异常发生了，进程还活着#

Process 执行 Python callable；subprocess.Popen 启动命令并立即交回控制对象。Slime 的 SubprocessInterpreter.run_file 用 Popen 跑文件，再用 communicate(timeout=...) 收集输出并等待退出。超过期限会抛 subprocess.TimeoutExpired，但这一调用不会自动杀进程。

try:
    stdout, stderr = proc.communicate(timeout=0.05)
except subprocess.TimeoutExpired:
    print("timeout still running", proc.poll() is None)
    proc.kill()
    stdout, stderr = proc.communicate()

第二次 communicate() 才完成输出读取、管道收尾和退出等待。不能只记一条“超时”日志就丢掉 proc。这是本例直接保留的源码顺序；命令替换成当前 Python 解释器的 time.sleep(60)，没有调用真实模型或工具服务。communicate 超时合同

        try:
            proc = subprocess.Popen(
                cmd,
                stdout=subprocess.PIPE,
                stderr=subprocess.PIPE,
                text=True,
                env=env,
                shell=False,  # Never use shell=True for security

            proc.kill()

proc.poll() 不阻塞：仍运行返回 None，结束返回退出码。proc.wait(timeout=...) 等待退出但不读取输出。给 stdout/stderr 配了 PIPE 却一直只 wait，孩子可能写满管道后等父进程读取；父进程同时等孩子退出。本例因此对捕获输出的进程使用 communicate，对丢弃输出的进程才直接 terminate()、wait()，超时再 kill()、wait()。Popen 等待与终止

        cmd = cmd[1:]

    child = subprocess.Popen(cmd, start_new_session=True)

    def terminate_child(signum, _frame):
        if child.poll() is None:
            child.terminate()
            try:
                child.wait(timeout=5)
                sys.exit(128 + signum)
            except subprocess.TimeoutExpired:
                pass

            try:
                os.killpg(child.pid, signum)
            except ProcessLookupError:
                pass
            try:
                child.wait(timeout=5)
            except subprocess.TimeoutExpired:
                try:
                    os.killpg(child.pid, signal.SIGKILL)
                except ProcessLookupError:
                    pass
                child.wait()

"""Teaching cut: STOP/COMPLETE protocol, then process and Pool cleanup."""

import multiprocessing
import time


def query_single_turn(client, messages, sampling_params):
    return messages + [{"role": "assistant", "content": "4"}], "stop"


def get_rule_based_math_reward(item):
    return int(item["messages"][-1]["content"] == item["label"])


def worker_process(task_queue, done_queue, rollout_func, reward_func, client, sampling_params):
    for item in iter(task_queue.get, "STOP"):
        messages, finish_reason = rollout_func(client, item["prompt"], sampling_params)
        item["messages"] = messages
        output_item = {
            "messages": messages,
            "reward": reward_func(item),
            "instance_id": item["instance_id"],
            "extra_info": {"finish_reason": finish_reason},
        }
        done_queue.put(output_item)
    done_queue.put("COMPLETE")


def read_data_into_queue(task_queue):
    for instance_id in (10, 11):
        task_queue.put({"instance_id": instance_id, "prompt": [], "label": "4"})
    task_queue.put("STOP")


def conversion_worker(value):
    return value * value


def main():
    ctx = multiprocessing.get_context("spawn")
    task_queue, done_queue = ctx.Queue(maxsize=4), ctx.Queue(maxsize=4)
    processes = []
    try:
        process = ctx.Process(
            target=worker_process,
            args=(task_queue, done_queue, query_single_turn, get_rule_based_math_reward, None, {}),
        )
        process.start()
        processes.append(process)
        print("owned worker", process.pid in {child.pid for child in multiprocessing.active_children()})

        producer = ctx.Process(target=read_data_into_queue, args=(task_queue,))
        producer.start()
        processes.append(producer)
        results = []
        while True:
            item = done_queue.get(timeout=10)
            if item == "COMPLETE":
                break
            results.append((item["instance_id"], item["reward"]))
        print("results", sorted(results))
        for process in processes:
            process.join(timeout=5)
            if process.is_alive() or process.exitcode != 0:
                raise RuntimeError("worker did not exit successfully")
        print("joined", all(not process.is_alive() for process in processes))
    finally:
        for process in processes:
            if process.is_alive():
                process.terminate()
                process.join(timeout=5)
            if process.is_alive():
                process.kill()
                process.join()
            process.close()
        for queue in (task_queue, done_queue):
            queue.close()
            queue.join_thread()

    process = ctx.Process(target=time.sleep, args=(60,))
    process.start()
    try:
        process.join(timeout=0.01)
        print("join timed out", process.is_alive())
    finally:
        if process.is_alive():
            process.terminate()
            process.join(timeout=5)
        if process.is_alive():
            process.kill()
            process.join()
        print("process reaped", not process.is_alive())
        process.close()

    pool = ctx.Pool(2)
    try:
        print("pool", pool.starmap(conversion_worker, [(2,), (3,)]))
        pool.close()
    except BaseException:
        pool.terminate()
        raise
    finally:
        pool.join()


if __name__ == "__main__":
    main()
