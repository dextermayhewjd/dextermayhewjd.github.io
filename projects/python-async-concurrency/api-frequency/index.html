01–41 课：全部 API 与语法出现次数

按首次引入顺序查看 98 项 API 与语法的四库次数；同课知识点一起计算本课占比，辅助安排学习侧重。

当前学习位置： 36.2 尚未读懂，暂时跳过；24.1 的 ContextVar 基础已初步理解，当前学习 24.2 的 token/reset，此前 call_later 教学与create_task 与 call_soon可回顾。查看学习记录与续学入口；下面保留完整统计，次数与标色不表示已经掌握。

按完整课程规划的 41 个编号单元排列，包含全部 98 项 API / 方法 / 装饰器和 7 项语法。 每项只放在首次正式引入的课程中，同一课只在第一行显示课号。第 10 课回访 gather；第 11 课回访 TaskGroup，并首次正式引入 except*，不重复计入已有 API。

01–22、24–38 已整理；23、39–41 待编写。 后续课程先列出规划中的接口及使用次数，列入本表不表示教程已经写完；“待编写”课号链接到对应模块的课程规划。

数字来自四个仓库固定快照的核心包静态位置，排除测试和示例；不是程序运行时的执行频率。每个 API 单独一行，构造与方法分开。单项明细保留调用、语法、引用的统计口径；课程占比统一按知识点出现次数计算。

四库按调用量加权：1614/1899（85.0%）；扩充前 82 项为 1528/1899（80.5%）。分子是所选接口对应的去重调用位置数，分母是四库全部已识别相关调用位置数，不平均四个仓库的百分比。新增子课仍待编写，具体安排见完整课程规划。

每个统计项都给出“四库合计”和“占同类总量”：调用位置除以 1899，语法位置除以本表七项语法的合计 4300，装饰器引用除以已识别 API 引用的合计 644。分母随“统计口径”而定，三类百分比不相加；调用占比保持原口径。第 10 课只是复用前课，标为“复用前课”，不重复计数。窄屏可左右滑动查看合计和百分比。

怎样看整节课： 最右侧“本课占比”把同课各项的四库使用次数相加，再除以四库整体统计总量，跨本课所有明细行显示一次。当前统一分母为 1899 个 API 调用位置 + 4300 个语法位置 + 644 个 API 引用位置 = 6843；其中调用和引用包含尚未选入课程的接口，语法沿用本表七类统计范围。例如第 1 课把 async def 和 asyncio.run 一起计算：1557 / 6843 = 22.75%。原有单项占比保持不变，不平均四个仓库的百分比。

“本课占比”与单项“占同类总量”的分母不同：前者看本课组合占整体统计范围的比例，后者保留各类明细的原口径。同一行代码涉及多个知识点时分别计数；因此它不是去重代码行覆盖率，也不是运行时执行频率。课程尚未包含所有已识别接口，各课占比不需要加到 100%。复习旧 API 不再次计数，纯复习课标为“复用前课”。

颜色图例：同类占比 ≥ 1% 标蓝色合计与占比；Slime 次数 ≥ 5 单独标红色 Slime 数字及对应 API / 语法名称；其他三库仍按单库次数 ≥ 10 标橙色。右侧“本课占比”达到 1% 时同样标蓝，但使用课程份额的分母；该列用底色和分隔线区分。

学习提示： 课程占比帮助判断哪些知识点整体更常出现，适合增加练习和源码对照；低频不等于不重要，取消、清理、异常与必要前置仍按课程顺序学习。
