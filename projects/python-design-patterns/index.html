Python 设计模式

统一使用 Python 3.12，从实际问题理解 22 种模式与可运行示例。

先看问题，再看模式#

同一件事可能用普通函数就能做好，也可能需要对象组合。设计模式提供的是处理变化、依赖和协作的方法；实际写 Python 时，函数、生成器、dataclass 和 Protocol 都可以表达其中的一部分。

这里整理本地 back_to_design_pattern 的 22 种模式，所有主例统一采用该项目的 Python 3.12 原例。保留原例的类、方法、类型参数和调用方式，只补充关键行中文注释；讲解与运行输出同步核对。旧版原例和传统类结构仅在文末作为历史对照。

这里说的“Python 3.12 设计模式”，是使用 Python 3.12 实现的设计模式示例。模式本身不属于某个 Python 版本，也不是 Python 官方定义的一套新版模式。type、类型参数与 @override 使用 3.12 的能力，Self 等较早已有的语法仍然适用。有些原例是最小结构或 Python 替代表达，具体边界在各页说明。

阅读假设：认识函数、参数、返回值和类的实例即可。遇到陌生语法，可以先跟随示例的观察点，弄清对象和数据怎样变化。

可以从工厂方法开始：先看 Python 3.12 原例和输出，再按疑问展开独立知识块，最后用一句话收拢设计职责。

从一个具体需求开始#

现在的问题可以先看
同一流程，要切换计算方法策略：把函数当作参数
给已有函数增加日志或计时装饰器：包装原有行为
新旧接口不一致适配器：转换接口
一个变化要通知多个地方观察者：登记和调用回调
想逐项读取数据迭代器：yield 与生成器
创建对象时有多种选择工厂方法：集中创建入口

这些是按问题查找的入口，不要求按顺序读完所有模式。

三类模式#

创建型 · 5 种#

怎样创建和配置对象。

模式解决的问题
工厂方法 · Factory Method把创建对象的选择放到一个入口里。
抽象工厂 · Abstract Factory一次选择一整套相互匹配的对象。
建造者 · Builder把复杂对象的配置和构造组织清楚。
原型 · Prototype基于已有对象，复制并调整少量状态。
单例 · Singleton让调用方复用同一个实例。

结构型 · 7 种#

怎样连接接口和组合对象。

模式解决的问题
适配器 · Adapter把现有接口转换为调用方期待的接口。
桥接 · Bridge让两个变化维度可以独立组合。
组合 · Composite用一致的方式处理单个元素和嵌套容器。
装饰器 · Decorator在现有行为外面逐层添加功能。
外观 · Facade为一组子系统提供一个方便的调用入口。
享元 · Flyweight让大量对象共享可复用的状态。
代理 · Proxy在访问真实对象时加入控制。

行为型 · 10 种#

怎样分配行为和协调协作。

模式解决的问题
责任链 · Chain of Responsibility让请求依次经过多个可选择处理的环节。
命令 · Command把一次操作保存成以后可以执行的值。
迭代器 · Iterator逐个产生元素，让调用方不必了解内部结构。
中介者 · Mediator把多个参与者之间的协作集中到一个中间角色。
备忘录 · Memento保存状态快照，以便以后恢复。
观察者 · Observer一次状态变化，通知多个订阅者。
状态 · State让同一个对象在不同状态下响应不同。
策略 · Strategy保持调用流程不变，替换其中的算法。
模板方法 · Template Method固定处理步骤，把可变化的步骤留给调用方。
访问者 · Visitor针对一组对象类型增加新的操作。
