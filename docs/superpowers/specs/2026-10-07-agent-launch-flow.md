# 启动 Agent 独立样例

用户已批准总图优先的任务样例，默认 mentalModel 根图。网站实现，主线程提供当前源码的精确 flow 包；不扩展 17 课、不发布。

## 最新反馈：总图优先

默认改为编号分层总图，不自动展示源码。点击步骤展开子流程，明确选择看源码后才进入已有阅读器。常驻栏显示完整编号路径和回总图；原文件路径单独保留。

业务主线以最新源码模型为准：0 会话准备、1 创建沙箱并安装 CLI、2 准备 workspace、3 harness.run、4 收集 diff、5 独立评估、6 结果分支，最后清理。3 内部分为确认用户权限、写配置和 launch_and_wait，再展开 run_agent、后台执行与轮询。ensure_agent_user 不是创建沙箱。

模型的父子、顺序和条件来自主线程，不从函数边猜测流程。业务箭头不是历史演化；点击图或切换源码仍不写理解记录。源码阅读器的目录、上下游、返回和显式勾选继续保留。本条覆盖此前默认直接打开函数的设计。

## 布局与交互

首屏展示 0–7 正常路径、结果分支与最后清理。每层显示当前父框和直属子步骤，常驻编号 trail 与总流程入口；图上点步不自动打开源码。

明确看源码后才显示短解释、源码和一层上下游。源码 path 与流程编号分别显示；右侧保持相关 folder/file/function 树。目录/函数跳转从当前 trail 选择最接近位置；返回记录 nodeId/stepId/layer，回流程图保留原层。

函数正文预渲染，切换只隐藏/显示对应面板。文件树不重建，只更新高亮，保留展开状态；键盘和窄屏也能导航。

看过／当前焦点与能解释分开。默认函数算打开过，不算理解；手动勾选“我能解释这个函数”按 flow＋准确函数来源/记录键保存在浏览器。页面访问、返回、源码展开和业务骨架不写理解记录。

## 数据接口

以主线程 agent-launch-flow.json 为准，保留 repository/revision/flow ID/defaultNode。每个函数有稳定 ID、准确 path/symbol/range/text、简述、直接上下游和理解记录键；业务步骤是上层框架，不伪造完整执行记录。树从本样例函数的真实路径生成。

源码数据到达后原样呈现，不自行扩写机制解释。来源更多细节折叠，不把旧 25 步面板、645 文件目录或全仓审计带入样例。

## 验收

- 默认根图，无自动长源码；八个编号步骤、可见箭头和父框。
- harness 的 3.1/3.2/3.3 下钻正确；同一 ensure_user 的 2.1 与 3.1 保持独立流程位置；choice 分叉不是串行。
- 上下游／文件树／返回同步函数、流程 trail、源码路径与树高亮，回图保留层级。
- 树展开状态保持，键盘可操作，手机不横向溢出。
- 浏览不标掌握，手动理解可保存、刷新恢复、取消；不同 flow/源码记录隔离。
- 课程入口提供体验链接；既有小课和 LCC 保持原行为。
