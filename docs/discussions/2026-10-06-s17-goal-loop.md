## 定位与源码边界

Goal 检查接在主模型无工具调用的返回位置；工作循环负责行动，controller 决定是否允许结束。README 的“会话级 Stop hook”是职责说明，具体代码在 AgentSession._run_query 内直接 await evaluate_after_turn，没有注册进 hooks["Stop"]。普通摘要 Stop 在非 block 返回时执行。

S16 导入 S15 并扩展工具池；S17 是重新基于 S04 Kernel 的独立五工具脚本，没有导入 S15/S16。总览的累积学习骨架与真实源码分开说明，避免把旧能力复习索引当成实际集成。

## 需要与源码一致的细节

1. /goal 查询、清除是宿主命令，不是 TOOLS；新条件立即当任务执行。会话只有一个活跃目标。
2. 只在无工具结果的轮次判断；评估器另一次请求没有 tools，也不能自行读取文件或验证测试。
3. 评估副本默认 24000 字符，保留最近完整消息，过大最新消息保留头尾。没有修改主循环 messages，早期证据可能不在副本里。提示要求读证据不等于机械验证，也没有可信来源过滤。
4. JSON 校验只保证字段结构；ok 与 impossible 不可同时为真。评估调用或解析失败返回 error，保留目标。
5. 默认连续阻止上限为 8：允许 8 次 block，第 9 次未满足返回 limit。max_turns 计数变量在一次 _run_query 内，新的提交或后台交付重新计数；目标不带默认 20 轮预算。
6. defer 先返回、不评估、不内部等待；宿主稍后交付才续跑。默认 CLI 的 background_running 为 false，没有后台启动／通知队列。S16 同步 Workflow 等整次运行返回，不能默认说它产生 defer。
7. goal_status 记录在内存 events。restore 只恢复最后一个仍 active 的条件，统计重新开始。CLI 不存盘／加载；不会恢复 messages、后台任务或 Python 现场。
8. status 的 Tokens 只统计主模型，评估器另有成本。一次命令行进程退出后，保留的活跃状态不会自动跨进程留存。
