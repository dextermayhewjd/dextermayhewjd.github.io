# Learn Claude Code 博客写作与架构图规则

本文件保存目前已确认的学习笔记规则，供后续章节和旧章节修订使用。核心目标：读者在当前页面就能认出上一轮系统，理解本轮改动的位置，再通过局部图和代码理解新机制。

通用方法与可生成的草稿见 [用架构图拆解核心机制](diagram-reading-method.md)。它是后续阅读笔记的可选格式；本文件继续保存 Learn Claude Code 的章节决定与网站实现约定。

关于模块归属与有限折叠，已保存 [原始讨论](discussions/2026-10-04-diagram-colors-and-abstraction.md) 与 [采用决定](discussions/2026-10-04-diagram-adoption-decision.md)。S03 已采用保留文件工具的画法，并在 S04、S05 延续；独立框是当前布局选择，不是每个能力永久独立成框的要求。

## 1. 章节组织与命名

- 按项目或课程组织方向，每个方向有总览、左侧导航和章节页面。
- 章节名称统一为“编号 + 英文主题 + 一句中文解释”，例如 `S02 Tool Use：工具增加，循环不变`。
- 左侧导航、总览中的章节卡片、文章标题使用同一名称，不另设缩短后的导航标题。
- 主线目前按新版 S01–S17 排列。需要深入解释的主题可以拆成子章节，主页面保留整体脉络。
- 编号迁移应在总览保留主题映射；正文注明所用教学代码的版本范围。目录编号更新不代表正文代码已经更新。

## 2. 文章结构与文字深度

沿用 S01–S06 的学习笔记风格：

1. **我想弄清楚的问题**：说明上一轮留下的问题，以及本轮为何需要新机制。
2. **整体过程**：先回顾上一轮，再展示本轮改造，最后拆出最小核心。
3. **逐步解释代码**：按机制拆成小段，每段代码前交代目的，后说明关键行为。
4. **串回主循环**：用伪代码展示新机制接入原 Agent Loop 的具体位置。
5. **边界与自己的理解**：说明实现的限制、容易误解的地方，并提炼一句自己的理解。

精简重复、空泛的文字，保留必要的解释、代码、状态与分支。不要因为“简洁”而删除理解机制所需的内容，也不要把整套实现集中成一个大代码块后才解释。

文章用自己的理解组织内容；借鉴教学仓库的结构、图和实现时保留来源，不逐段照抄原文。

- 连线选中保留原色与线型，通过加粗和不透明度变化表达；箭头头部独立限制为 12px，避免粗线把箭头放大到重叠。汇入主循环的分支明确标注汇入，不当作新增执行顺序。
- 已有节点也可以独立追踪关系，无须打开新的代码面板；章节链接继续正常跳转。本章模块沿用详情入口。再次点击、Esc 或恢复默认清除追踪，不改变第一张回顾图。
- 详情面板提供“只看连线”：收起面板但保留当前节点及箭头高亮，避免面板遮挡需要追踪的路径；再次点击模块恢复详情。
- 详情复用正文的局部图和代码；复制图时给内部 ID 与箭头引用加独立前缀，避免同页冲突。七个模块是本次 S08 的覆盖范围，不是认知容量上限。
- S08 局部详情把图与对应函数放在同一个阅读区，上方图、下方函数列表各自滚动。函数来自正文，不另写替代实现；步骤映射放在 `explorer.json`，多函数步骤全部提供代码。判断框明确关联 `estimate_chars` 与 `prepare`，不虚构额外函数。
- 指针进入步骤时预览高亮；点击或键盘 Enter／Space 固定选择并将对应函数移入代码区，整页和原总图不滚动。代码标题也能反向标出相关图节点。选中只加粗边框，不改变演化颜色。
- 无 JavaScript 时保留原生单组 details、模块摘要和正文链接；键盘可操作 SVG 模块和按钮，状态变化可被辅助技术感知。
- 就近详情提供关闭按钮与 Esc；默认打开时保持在视窗内，不覆盖所选节点。验证位置、整页滚动量以及图的几何和颜色，不能只确认点击后出现了内容。
- S08 详情支持拖动右下角调整宽高、方向键微调、放大与恢复尺寸。拖动以外必须有按钮操作。手动放大允许暂时遮挡更多总图，但不改变总图布局；恢复尺寸回到节点附近，关闭后清除本次尺寸选择，不写入下一章默认视图。
- 先验证单模块切换、恢复默认、图 1 隔离、总图几何与颜色稳定、窄屏可读性。再请读者依据默认总览回答位置、入口、成本、继续方式四个问题；构建或交互测试通过不代表学习效果已经验证。

- 功能本身被修改或职责迁移：图 2 用橙色，说明实际改动。
- 功能真正被删除：使用红色虚线／删除线历史标记，不接入当前执行路径。

S03 已取消“文件工具合并到 TOOLS”的旧画法：TOOLS 包含工具定义，实际函数由分发表调用。当前总图继续保留文件工具框。将来若折叠内部实现，应归入工具执行部分，并说明保留哪些能力；不能仅因相关就把定义与实现视为同一容器。

这是对蓝色基线的辅助标记，不是第五种系统变化颜色，也不要求标注所有旧细节。只有前后图的对应关系容易误解时才使用。与“原有 · 本轮展开”配合：图 1 提示旧细节将合并，图 2 提示旧细节首次展开，两者都属于阅读层面的变化。

### 为什么首次展开的旧步骤仍用蓝色

需要分别回答两个问题：

| 判断角度 | 要回答的问题 | 视觉表达 |
|---|---|---|
| 系统变化 | 上一轮是否已有？本轮是否改变？ | 框的颜色 |
| 阅读变化 | 读者是否第一次单独看到这个步骤？ | 灰色来源标签 |

用户输入在系统层面是已有步骤，在阅读层面是首次展开的细节。因此保留蓝色框，同时标注“原有 · 本轮展开”，不增加第五种变化颜色。也不只画一个没有来源说明的蓝色框，以免读者误以为上一张图已经显式画过它。

标签应使用较小的灰色文字，作为辅助信息，不使用额外的醒目底色或粗边框。首次展开的旧步骤帮助定位新机制；本轮新增或改造的机制才是注意力重点。

以 S04 为例，重点是蓝色用户输入与蓝色对话历史之间新增了紫色 `UserPromptSubmit`。输入框内可以写：

> **用户输入**\
> 原有 · 本轮展开

正文只需补一句来源说明：

> 上一章将输入步骤省略在历史写入之前；本章为解释输入 Hook，才将它单独展开。

这一选择借鉴多媒体学习中的提示原则：有目的的视觉提示可以帮助读者关注相关信息、建立文字与图之间的联系。该原则并不意味着颜色越多越好。研究依据见 [Richter、Scheiter 与 Eitel 的提示研究综述](https://www.sciencedirect.com/science/article/pii/S1747938X15000664)。

“颜色表示系统变化、标签表示首次展开”是结合本博客学习目标作出的设计判断，不是该研究直接验证过的最佳配色方案。

### S04 的具体例子

- 图 1 引用 S03 总图的结构，蓝色保留、橙色标出将改造的旧权限检查，不补画用户输入。
- 用户输入早已存在，S04 为解释输入事件才将其独立画出：蓝色，标注“原有 · 本轮展开”。
- `UserPromptSubmit` 是新事件：紫色。
- S03 的权限检查在 S04 回顾图中用橙色标出本轮将改造的旧位置；S04 将其改成权限回调，在本轮图中仍使用橙色展示改造结果。
- 原结束动作保留为蓝色，新增 `Stop` 事件为紫色。
- 权限保护没有消失，不画成红色删除后再新增一套保护。

## 5. 布局、连线与可读性

- 主流程从左到右，返回循环放在主线下方。
- 分支靠近对应判断，减少交叉、重复箭头和上下同时绕行的回环。
- 总图保持紧凑；保留理解整体机制所需的能力与接口，内部细节交给局部图。不要仅因上一章已经讲过就省掉该模块。
- 简单图默认画布及显示宽度为 760；S08 图 2 起的复杂总图使用 1200 宽画布，通过 shortcode 的 `width="1200"` 同时扩展实际显示区域。S09 图 1 继承 S08 的同一画布尺寸。高度按内容调整，文字字号保持不变。
- 扩展画布时同步检查节点间距与连线路由，不能只扩大 `viewBox` 或拉伸旧图。不同分支使用独立通道和接入点，避免共享一段重合线、穿过节点；明确汇入主循环的位置可以相交。窄屏只在图内横向滚动，不撑宽整页。
- `width` 只作用于指定总图；详情里的局部图保持原来的阅读尺寸。较宽文章页为总图提供空间，正文段落仍限制阅读行长。
- 箭头表示控制流或数据流时，应通过文字说明含义。
- 灰色虚线可以表示注册、关联等关系，必须说明它不是另一条执行循环。
- 同一张图尽量保持一致的抽象层次；展开旧细节时解释它原先隐含在哪一步。
- 颜色之外也使用文字标签、虚线或删除线，避免只能依赖颜色辨别。

### 总图成长与有限折叠

必须保留主循环、关键判断、模块接口、状态读写位置及影响控制流的分支。优先保持已有模块的相对位置、名称和归属；本轮总图可以调整局部间距、成员排列和画布尺寸。回顾图仍复用上一章实际结构。

折叠前检查：谁调用它、它处理什么、结果交给谁、会不会改变流程，是否仍然清楚。只有这些信息不丢失时，才折叠内部细节，并保留成员名称或职责摘要。工具变多后可组织为“可调用的工具实现”分组，不要求每个能力永远拥有独立框。

S03 保留文件工具框增加了少量画布高度，也延长了权限路径；这是当前学习阶段的具体权衡。后续若固定坐标使关键路径难读，应允许局部移位，而不是继续扩大绕行。

### 旧能力在原工具小框中简记，本章机制完整展开

沿用分发入口旁原有的紧凑工具框。文件工具仍简记为 `read / write / edit / glob`，已经讲过的其他能力只增加一条来源链接，例如 `TODO → S05`。框的标题可用“工具实现”，但不因增加索引就改造成下方的大目录，也不单独展开 Shell、文件工具等旧能力卡片。

- **S06 第二张图省略的是 S05 TodoWrite 的展开实现，保留的是 S06 Subagent 的完整结构。** task、独立消息历史、子循环、子配置与返回路径仍连接到主系统，像 S05 当时展开 TodoWrite 一样。
- 第三张图进一步拆解本章核心，不能用第三张图代替第二张图中应有的新机制整体结构。
- 旧能力的简记与章节链接放在原工具小框内；不另画成横向能力目录、多个旧工具卡片或大分组区。
- 章节编号说明实现在哪里讲过，颜色说明本轮变化。补一个索引不等于新加一个运行模块。
- 第一张仍回顾上一章的实际结构；对旧机制的简记只用于本轮第二张图。
- S08 从 S07.9 的整体图继续：Skills 的“调用／准备／交付”可合并成蓝色的装载接口，并保留 S07 章节链接；可见目录进入模型请求、正文进入历史这两条关系必须保留。不能将整个 Skills 机制归入工具实现框。图 1 用灰色虚线提示三个内部步骤的合并，原结构不变。
- Context Compact 的主体接在消息历史与模型请求之间。S08 当前展开 repo 的完整管线，主动 `compact` 工具在本批结果交齐后直接请求摘要；保留旧接口时注明复习范围，不能画成源码已经包含的工具注册。
- 按当前源码说明能力是否存在。S06 的 TODO 链接注明“历史索引，本例未含”，不表示当前分发表包含它；也不再把管理器、提醒等旧实现画成大块历史面板。
- 三轮提醒属于父循环；可以在正文链接到 S05 的提醒段落，不把它归入工具 handler。
- 修改图时同步核对图例、颜色和章节链接；保留稳定段落锚点，方便复习具体实现。
- 若以后小框确实容纳不下更多条目，再单独讨论排版；不要自动展开全部旧能力。

任务依赖图可以使用状态配色：绿色已完成、蓝色进行中、灰色待处理。它表达的是任务状态，应单独给出图例，不与模块变化配色混用；文字还要区分“尚待认领”和“被依赖阻塞”。

## 6. 代码、伪代码与依据

- 每个关键机制都提供必要的代码或伪代码，不能只有文字。
- 小段代码解释局部机制，最后的整体伪代码把它接回已有循环。
- 保留理解行为所需的输入 schema、状态、返回值和分支，不只展示函数名。
- 图、正文、代码和伪代码应描述同一套实现。
- 区分教学仓库的实际实现、官方公开行为，以及为理解机制编写的示意实现。
- 讨论现代 Claude 行为时核对当前官方文档。官方没有公开的内部细节，不写成已确认的产品实现。
- 基于官方行为设计的可能代码，应明确标注为教学示意，并说明哪些是自己的实现选择。
- 对照新旧版本时按主题核对，不只按章节编号比较。


基线模式保留功能节点与连线，只在显示时统一功能配色、使用中性标题、隐藏带 `data-evolution-legend="true"` 的旧变化图例，并采用 `data-baseline-label` 指定的中性说明。需要标出旧模块将改造时，增加 `modified="execute"`（多个标识用逗号分隔），只改变回顾图里的框颜色，源图不变。需要提示细节合并时，增加 `folded="added-file-tools"`，按源 SVG 的 `data-stage` 标识选中框；图注必须说明合并去向。源 SVG 和原章节第二张图的配色保持不变。

SVG 使用唯一的 `title`、`desc` 和箭头 ID，提供描述与可访问标签。颜色通过网站 CSS 变量设置并提供默认值，支持浅色和深色主题；窄屏在图内横向滚动，避免撑宽整页。图使用原生 SVG，不依赖外部绘图脚本。
