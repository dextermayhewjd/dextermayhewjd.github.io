当前 Agent Sandbox 的 Step 000 已积累 9 个函数/方法记录和 1 张类卡，混合了初始骨架、对象初始化、环境准备、任务执行、命令通道及后来回查的数据来源。单纯调整索引顺序不能限制某一步实际读入的内容。

已有内容仍有保留价值。需要调整的是资料归属、当前步骤的选择范围，以及读取时机，不能把“移出当前 step”解释成删除已读事实或清零认识。

## 2. 推荐的三项分工

| 位置 | 保存什么 | 能否自动视为本步已经接触 |
| --- | --- | --- |
| 项目级 function-library | 可复用的完整函数/类资料，保留源码版本、原始学习来源、原话与未知 | 不能。它是候选资料，不是当前步骤的已读清单 |
| step 的 02-short-term-memory | 当前明确选中的函数，以及这一步使用或更新的学习快照 | 只有本步实际采用的记录才进入 |
| 既有 history 与 step 的 03-long-term-memory | 历史记录及真实前序学习的继承快照 | 按历史来源解释，不因目录排序自动增加掌握状态 |

function-library 不替代 03。前者回答“有哪些资料可查”，后者回答“这一步之前已经留下了哪些认识和未知”。

## 3. 目录示意

以下为目标结构示意，不表示这些目录已经创建，也不预定新步骤编号。

```text
agent-sandbox/
  function-library/
    README.md
    functions/<source-path>/<function>.md
    classes/<source-path>/<class>.md
  history/
    initial-exploration-2026-11-04/
  steps/
    step-NNN-<question>/
      README.md
      01-scope.md
      02-short-term-memory/
        overview.md
        functions/<source-path>/<selected-function>.md
      03-long-term-memory/
      04-flow.md
```

例如，一个只讨论“main 怎样把任务和回调交给 Fleet”的步骤，02 只需要 main 的当步记录。run_naive、setup、process_parallel 等可以在骨架中出现并保留资料入口，但不因此自动进入本步短期记忆。

若该步骤已经明确包含 main 与 run_naive 两个函数，则只纳入这两张。其他函数要在对应问题真正开始后再纳入。

## 4. 怎样防止再次混入全量资料

1. **先在 scope 写明本步问题与函数边界。** 02 的 overview 只列实际选入的记录，不把总库目录复制过来。
2. **按本步问题读取。** 助手先读 scope 和当步记录，只在当前问题需要时查资料库中的具体文件，不批量读完整库。
3. **骨架出现调用，不等于进入该函数。** 旁支先保留职责与源码定位；需要扩大核心范围时再按既有约定确定。
4. **总库保存完整版，步骤保存当步版本。** 从库中调取时明确来源、源码版本与本步要看的层次；较长的扩展讲解保留在库或 reference。不能把后来新增的解释自动当成早期步骤已经知道的内容。
5. **当前讨论只更新当步记录。** 新认识、原话和纠正先记入当前 02/04；需要形成可复用资料时，再带着来源整理回资料库，避免两份正文无来源地同时修改。
6. **保留冻结的历史。** 后续资料库改动不反向覆盖已结束的步骤快照。单纯让所有旧步骤链接到一个不断变化的最新卡片，无法保存当时的认知状态。

当前仍沿用函数卡的场景、输入输出、LLM 整理、原话、未知和来源格式。本方案不把 02 降为只有目录链接，也不要求把所有辅助函数拆成新卡。

4. 调入的记录保留旧来源和已表达的认识；迁移、缩减展示或重新阅读本身不算新的掌握。
5. 03 仍按真实前序学习记录承接，不直接导入整个资料库。现有探索历史怎样接到重组后的步骤，应在迁移说明中明确登记，不能为了让 02 看起来整洁而抹去已有认识。
6. 核对全部相对链接、来源锚点和当前进度入口。未来尚未开始的步骤只留在路线方案中，不预填学习完成记录。

实际迁移前，需把采用的步骤边界与旧历史的承接方式一并确定。本轮先给出结构方案；现有学习记录保留在原位置。
