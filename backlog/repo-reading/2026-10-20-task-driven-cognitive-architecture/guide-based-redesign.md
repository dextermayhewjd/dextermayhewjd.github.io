# 按两条指南重新设计阅读步骤

状态：讨论稿。依据用户已保存的[代码阅读指南](../../../00-repo-reading/code-reading-guide.md)，提出当前系统的调整方式；本稿不直接改写现有步骤、模板或 skill。

## 核心定义

**一个 Step 围绕一个需要解释的问题，建立一段可以说清的数据变化或调用交接。**

函数是为回答问题而进入的阅读对象，也是可复用记忆的记录单位。Step 不必等于一个函数，也不以函数清单全部填满为完成条件。

两条指南分别控制两件事：剪枝决定这次看多少，记录方法决定哪些内容值得留下。目标是让下一次阅读能接着已有主线继续，而不是扩大文件数量。

## 保留目录，明确每处保存什么

| 位置 | 核心职责 | 主要内容 |
| --- | --- | --- |
| 步骤 `README.md` | 看见本步问题与主线 | 一个具体问题、裁剪后的调用骨架、关键数据交接、本步展开位置与下一问；链接函数记忆 |
| `01-scope.md` | 限制本步范围 | 为什么现在读、入口条件、涉及哪些函数、哪些先留白、读到哪里停止 |
| `02-short-term-memory/` | 保存本步可复用的函数认识 | 实际展开的函数及其新增或修正认识；原话、场景、输入输出、LLM 模型、未知和来源 |
| `03-long-term-memory/` | 提供前序积累 | 上一步 `03 + 02` 的完整继承；Step 0 继续为空，overview 仍只做索引 |
| `04-flow.md` | 保存真实问题与认识变化 | 实际提问、助手解释、源码依据、用户反馈及后续修正，链接最终函数记录 |

完整函数说明只维护在函数卡片中；步骤主线只保留足以理解交接的短标签与箭头，不再次复制长输入输出。

## 四种记录怎样落到现有结构

### 数据变化

局部变化放函数卡片的 Input → Output；跨函数交接放步骤 README。例如下面只是系统层面的两条关系，不是对每个辅助函数的展开：

```text
任务信息 → Agent 执行 → diff → 独立评测 → reward
基础样本 + 模型交互轨迹 + reward → Samples
```

第二条明确样本还依赖模型交互轨迹与基础样本，不能把 reward 当作生成训练数据的唯一输入。

### 临时路径

阅读中只维护当前追踪目标与返回位置。例如“从任务入口追到模型请求，当前看转换，读完返回调用处”。临时路径可以替换或丢弃；实际形成的理解与修正仍保留在正式记录中。

本步主线是当时的学习快照；全局实时进度仍只在项目既有的唯一进度记录中维护。

### 疑点与设计取舍

问题出现时记入 `04-flow.md`。得到证据后，把有助于复用的结论补到对应函数记录并保留来源。没有证据的 Why 继续标为假设或未知，不用一个合理故事代替源码依据。

### Git diff 等局部观察

可作为特定问题的辅助材料，不另建必填步骤。本仓库现有函数记忆和过程记录继续保留；保存方法文章本身不授权改动被阅读仓库、提交代码或删除已有笔记。

## 一步怎样推进

1. **选问题。** 助手定位主流程，提出本步要解释的交接与所需函数，由用户确认。已有明确指定时沿用，不重复询问。
2. **剪枝。** 展示正常路径，暂时折叠配置、日志、检查与失败分支；省略处仍注明边界。
3. **读一个有关的局部。** 下钻不超过两层，能说明本步关心的输入输出或交接就返回；不要求把遇见的全部符号展开。
4. **记录实际结果。** 更新主线与实际展开的函数卡片，保留疑点、证据和用户反馈。没有新的认识，不为填满目录而制造内容。
5. **接续。** 留下一个由当前主线产生的下一问；实际进入下一步时再继承记忆，不预建未来的完成记录。

## 用当前 Coding Agent 做一个试用候选

候选问题：**一份代码任务怎样得到代码改动、评分和可交回的样本？**

第一步只使用指南中已有的 `generate` 正常路径裁剪，确定关键产物与交接；配置加载、日志、完整异常路径和各辅助函数内部先留白。后续再由具体问题决定是进入执行、模型请求还是评测，不把下面的函数列表变成固定课表。

已有 `_translate` 记录保留供进入模型请求环节时复用。看到 `open_session`、`run_evaluation` 等名字，不表示必须立即为它们创建完整函数卡片。

这个例子说明怎样试用新分工；本稿不把它写成用户已经确认的当前阅读步骤，也不改写旧记录。

## Skill 分工建议

| Skill | 状态 | 职责 |
| --- | --- | --- |
| `repo-reading-short-term-memory` | 已建立，继续使用 | 本步单函数记忆、输入输出、原话、未知、来源与共用记录引用 |
| `repo-reading-step` | 候选 | 选问题、剪枝、主线与数据交接、限制阅读深度，并整理本步实际问答 |
| `repo-reading-long-term-memory` | 候选 | 只负责继承、合并和来源保持；不承担选题或新的源码讲解 |

暂不单独创建临时路径或过程记录 skill。它们可以由步骤 skill 协同维护，先用一次实际阅读检验是否有必要继续拆分。现有 `repo-reading-memory` 继续承接总入口和未拆出的长期规则。

下一次检验的重点是：能否从一个具体问题，经过少量源码，留下可用的数据交接与函数认识，并清楚知道下一问在哪里。
