# 源码阅读：短期与长期记忆

保存学习者实际形成的理解，并配上原仓库的使用场景、调用代码、输入输出和 LLM 的场景模型，帮助下一次接续。个人理解来自学习者的表述；源码事实与 LLM 推断分别标明来源。此 skill 适用于任意源码仓库，不指定技术栈、岗位或课程路线。

## 一、记录规范

### 1. 四份记录各做什么

| 位置 | 内容 | 写入时机 |
| --- | --- | --- |
| `01-scope.md` | 为什么读、核心问题、入口条件、源码范围、阅读边界 | 开始本步时定位，范围变化时说明原因 |
| `02-short-term-memory/` | 本步新形成或修正的认识 | 根据学习者实际表述更新 |
| `03-long-term-memory/` | 进入本步前的完整累计模型 | 创建新步骤时继承 |
| `04-flow.md` | 实际问题、源码证据、助手提示、学习者表述及修正过程 | 随讨论记录 |

函数记忆中保留够用的源码场景和明确标为 LLM 提供的场景模型；完整助手讲解和扩展分析放 `references/`。学习者说“继续”、材料完成或源码核对成功，不表示接受了助手的全部解释。仅知道作用时，保存作用并保留实现未知；没有个人认识的符号只列为“已定位、尚无个人模型”，不能用 LLM 的解释代填。

### 2. 每层 memory 的目录

```text
02-short-term-memory/          03-long-term-memory/
├── overview.md               ├── overview.md
└── functions/                └── functions/
    └── 源码相对路径/              └── 源码相对路径/
        └── 完整函数名.md              └── 完整函数名.md
```

源码文件名成为笔记侧的同名目录。例如 `slime/agent/adapters/common.py` 中的 `BaseAdapter._translate` 对应 `functions/slime/agent/adapters/common.py/BaseAdapter._translate.md`。只创建实际需要的记录，不复制整个源码树。

共同接口的职责记在定义接口的符号下；协议或后端特有的认识记在具体实现下，两者互相链接。原文件只定义位置，不决定这项认识应归给哪个层次。

### 3. 每个函数文件的统一格式

标题使用完整函数名，开头保留首次接触、最近理解更新；源码定位集中到文末来源。默认使用[短期函数模板](references/short-term-memory-template.md)或[长期函数模板](references/long-term-memory-template.md)，正文相同，长期另注明继承来源。

| 项目 | 必须保留的内容 |
| --- | --- |
| 我的理解（原话） | 正文首先逐字保留学习者对函数的直接解释，以及关键追问后的补充；注明来源步骤或问题 |
| 使用场景与源码 | 简短说明当前任务、调用者与后续消费者，附几行真实调用代码 |
| Input → Output | 一组相互对应的小输入和当前函数的返回值或副作用，标明教学缩减或构造 |
| LLM 根据调用处补充的模型 | 简短说明职责与边界，区分代码事实和推断 |
| 暂时不清楚 | 已暴露的疑问和未展开的实现 |
| 来源 | 源码路径、固定版本与行号，样例来源与验证方式，原始步骤的 flow 段落链接 |

原话已经说清楚时，省去重复的“当前心智模型”栏目。确需整理零散表述时，可在原话后补一句“助手据原话归纳”，只保留有用的整理，不复写 LLM 模型。完整问答与长解释链接到原记录。

保留原话的措辞、口语和不准确处；助手澄清另写，不把纠正后的表达放进用户引文。节选时标明节选，不拼接成用户没有说过的句子。选择直接说明该函数的表述与关键补充，完整问答继续保存在 flow。

**默认使用短例子。** 场景用 1–2 句话说明“现在做什么、为何调用这里”，调用代码通常取 2–6 行；一组小输入输出只演示本轮关心的一处变化，LLM 模型通常 1–2 句话。此为控制篇幅的默认尺度，不为凑行数删掉必要关系。个人模型与 LLM 模型重合时简短对照，不再重复整段解释。

每次选一个当前正在阅读的代表场景，不复制整段主程序。摘录真实调用及够用的上下文，标明省略；回调或接口要交代注册点或具体实现，不能把基类占位方法当作实际执行体。调用处只能显示部分行为，需要时再核对相关实现。

输入输出优先从仓库测试、示例或已有样本缩减，保留真实接口与当前问题必要的字段；也可构造一份符合真实接口的最小教学输入。标注“教学缩减/构造”，不能称为真实用户请求。若输出只截取部分字段，明确写“输出节选”；输入缩减后重新核对对应输出，不能直接沿用完整输入的结果。静态推导与实际执行分开；能低成本运行纯函数核对时优先核对。不能确定的值标为未核对，不编造输出。

“最后输出”默认指当前函数或明确圈定的局部场景终点。当前函数返回值、调用者的后续结果、整个任务的最终产物分别注明；有副作用而无有意义返回值时写副作用。正文直接展示短输入输出，完整样本和长解释移到参考文件，通过链接按需展开。版本、执行范围和校验过程集中在元数据或折叠的来源说明，避免每节重复。

LLM 模型可以补充用户尚未表达的下游用途，必须明确属于源码解释。个人理解只记录用户已经表达的认识；没有反馈不能把 LLM 模型复制为个人理解。原话也不自动代表技术结论正确；已知问题放入未知，后续修正保留来源。不要求继续展开全部异常和内部算法。

### 4. overview.md 显示什么

- **所属步骤与记忆范围**：本步新认识或前序累计模型；长期记忆另列继承来源。
- **当前整体模型**：短期写本步新增或修正的关系，长期写已经积累的关系；只使用学习者实际表达的内容。
- **源码场景参考**：按需链接函数记录中的真实场景与 LLM 模型，和个人整体模型分开；不复制全部代码及样本。
- **函数索引**：源码文件、函数记录链接、首次接触、最近认识更新。仅定位的符号明确标注尚无个人模型。
- **尚不清楚**：尚未解释的整体或跨函数关系，局部未知可链接函数文件。
- **形成过程**：各项认识的原始步骤和 flow 链接。

没有前序模型时，长期 overview 写“暂无继承”，不创造占位的个人认识。未记录不能自动解释为遗忘，也不能抹掉用户明确报告的已读历史。

### 5. 通过复述与追问形成记忆

记录新认识时，按下面的互动推进；尚未得到的回答保持空缺。

1. **定位一个函数、一个问题。** 核对原仓库的使用场景和真实调用，准备一对输入输出；简短交代当前场景及为什么到这里。
2. **请学习者复述作用。** 先问“你现在怎么理解这个函数究竟完成了什么事情？”。先听其表述，再决定补什么；不先写出整段答案要求照着重复。
3. **根据回答追加细节问题。** 每次聚焦一个有用的区别，例如两份输出各有什么用途、转换与执行的边界、当前函数与下游如何交接。说明为什么追问这点；不照固定问卷逐项考完。实现细节尚未展开时可以保留未知。
4. **结合证据澄清。** 根据真实调用和输入输出给出 LLM 的场景模型，标出新增关系；有混淆时只展开相关源码或数据，让学习者再用自己的话表达发生变化的部分。助手解释和学习者后来的理解分开记录；“继续”不是后续复述。
5. **展示候选记忆。** 按统一格式先展示原话，再展示场景、调用代码、输入输出及 LLM 模型，最后对照个人已经表达的理解和未知。说明保留理由，让学习者指出遗漏或失真。已有准确表述可以直接保存，不把额外确认变成归档或继续阅读的门槛。

`04-flow.md` 留下实际发生的复述、追加问题及其目的、查看过的源码或数据、澄清和后续回答；函数文件在“来源”中链接回原始形成过程。提问计划和假设回答不能写成已发生的学习过程。

已有表述足以整理历史记录时直接沿用；用户明确要求重新模拟时，再实际邀请复述。进入下一步继承长期记忆时，不要求为所有旧函数重做问答。

**共同迭代此 skill 时，用真实互动检验格式。** 每轮先试一个函数，展示实际回答能形成的候选记录，再讨论提问是否有帮助、记录是否能恢复理解、哪些内容应删减。将用户明确提出的规则及时写入 skill，将尚待试用的格式标为草案；不代演用户回答，不把文件生成或静态检查当成学习效果验证。设计反馈保存在工作流讨论中，技术理解保存在相应步骤中。

### 6. 怎样更新和继承

先读已确认的项目、当前步骤、相关累计模型和最新表述，再决定更新哪个对象。沿用已有位置与源码版本，不另起一套进度或课程。带读时提供局部材料并邀请学习者解释；记录整理时不重复要求背诵已经说清的内容。

```text
第 N+1 步的 03 = 第 N 步的 03 + 第 N 步的 02
第 N+1 步的 02 = 等待新一步形成的认识
```

合并时按源码路径和符号保留完整记录，包括原话、场景代码、输入输出、LLM 模型、个人理解、来源与未知：新函数加入，旧函数有新认识时合并或明确修正，未在本步使用的旧函数继续继承。同一函数的短期记录保留使其独立可读的已有内容，不用一个新句子覆盖全部旧内容。进入长期记忆后仍保留各自作者与证据状态，不能把 LLM 模型变成用户已掌握的结论。

首次接触和源码证据保留原值；最近认识更新只随实际理解变化更新。复制、归档、改排版和新增助手解释不算认识更新。未知一起继承，未解决的冲突继续标明；不因进入长期记忆就变成已掌握。

**形成过程链接始终包含原始步骤名。** 新写的短期记录也使用“回到步骤父目录 → 原始步骤名 → `04-flow.md#锚点`”的相对路径，而不使用只定位到当前步骤的 `../04-flow.md`。overview 的形成过程链接同样遵守；普通导航链接仍可指向当前页所属步骤。用路径工具计算相对位置，合并后实际检查目标文件与锚点，而不只检查字符串。

例如 `steps/step-02/02-short-term-memory/functions/src/gateway/base.py/Gateway._respond.md` 的来源可写为 `../../../../../../step-02/04-flow.md#respond`。复制到同级 Step 03 的长期目录后，它仍指向 Step 02。若改变目录深度，先解析原链接的目标，再相对新位置重算；保留原步骤和锚点。

旧步骤保留当时快照。遇到旧版只有 `02-memory/` 的步骤，先保留它，再将已有模型按当前格式导入新步骤；已有明确未知与原始版本一并保留。范围授权仅是整理记忆时，不改源码、不发布、不创建未实际开始的后续学习记录。

### 7. 保存前核对

确认原话逐字保留；场景来自原仓库且标明具体实现；输入与输出对应，终点和验证方式清楚；LLM 模型有代码依据，个人理解未被它替换；原有记录、未知和未重访函数没有丢失；来源步骤、源码版本和链接正确。检查完成只说明记录有效，不说明用户已经掌握或运行过整个任务。
