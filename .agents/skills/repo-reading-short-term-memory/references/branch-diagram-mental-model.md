# 分支型函数的心智模型：图配合分类依据

[返回短期记忆 skill](../SKILL.md)

## 适用场景与放置位置

函数根据配置、输入或模式选择不同执行路径，且读者需要分清“有哪几类、每类进入哪里”时，采用**分支图 + 每层分类依据**。将它放在函数卡的 **LLM 整理 → 第三项「建议构建的心智模型」**，沿用引用块；其余栏目继续遵循基础样例。

先用一句话概括函数的整体职责，再给一张小图，最后用短句解释各层按什么分类。顺序流程、数据变化、资源生命周期采用适合它们的表达，不为使用本 reference 改写成选择树。

## 画图前先确定什么

- **当前路径**：从哪个调用者进入，关键配置和输入是什么。
- **分类条件**：保留决定分支的字段或条件，使图能回查源码；图的层级来自实际分派关系。
- **每层问题**：例如第一层区分“整批还是逐项”，第二层区分“自定义还是内置”。按源码说明条件与分类的关系，不将同一标签机械套给每层。
- **函数边界**：标出何处已进入下游函数；下游只补当前问题必需的分支，并说明适用路径。
- **交付结果**：图后交代返回什么、交给谁，避免只有分支而没有收束。

## 已认可示例：batched_async_rm

本例从 generate_and_rm 的缺分样本列表进入。全局自定义路径存在时整批委派；不存在时逐项调用 async_rm，后者仍可能采用单样本自定义函数。

下面可直接作为函数卡第三项的呈现参考；函数名、字段与条件来自真实源码，图是阅读裁剪，不是完整实现：

3. **建议构建的心智模型**：

   > 批量评分的分派入口：先按“怎么组织调用”分类，再看单个样本“选哪种评分方式”；最后把奖励列表交回父函数。
   >
   > ```text
   > batched_async_rm：批量分派
   > ├─ 有全局 custom_rm_path
   > │   └─ 自定义评分函数处理整批 samples
   > └─ 没有全局 custom_rm_path
   >     └─ 每个 sample 进入 async_rm：单样本评分选择
   >         ├─ 样本有 custom_rm_path → 自定义评分函数
   >         └─ 否则 → rm_type 选择框架已有的评分方式
   > ```
   >
   > **第一层按调用粒度分**：整批交给自定义函数 / 逐个交给 async_rm。
   >
   > **第二层按评分来源分**：样本自己的自定义函数 / rm_type 指定的已有方式。

### 示例的边界

- 第一层是 batched_async_rm 自身的分派，第二层是 async_rm 的最小回查。独立调用 async_rm 时还会检查全局 custom_rm_path；图示路径已经由上层确认该字段为 None，因此省略这个不命中的检查。
- load_function 加载 Python 评分函数，不等同于加载神经网络模型。不要从名字推断不存在的执行行为。
- 两个分支最后都交回奖励结果。默认路径用 gather 按输入顺序收集；自定义函数需要遵守批量结果约定。父函数负责写入 Sample.reward。
- 图保持可扫读；参数细节、原始代码、返回顺序和验证边界留在“本场景的输入与输出”或来源区，不在多处复制同一张图。

## 与其他记录的分工

| 位置 | 保存什么 |
| --- | --- |
| LLM 心智模型 | 一句职责、分支图、每层分类依据 |
| 本场景的输入与输出 | 实际输入与配置、连续源码、数据变化、返回调用者的位置 |
| 我的直接表述 | 用户真实表达；认可图形不等于确认全部机制 |
| 尚不清楚 | 尚未理解的分支、条件和下游行为 |
| 折叠来源 | 固定版本、源码定位、原始讨论和验证范围 |

主 skill 的其他栏目与函数边界继续有效；本 reference 是一种按需选用的心智模型表达，不取代整张函数卡。
