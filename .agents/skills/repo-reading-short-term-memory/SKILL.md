# 源码阅读：单函数短期记忆

负责本步 `02-short-term-memory/` 中的函数记录与索引。保存学习者实际表达的理解，并配上核对过的场景、调用代码、输入输出和 LLM 模型。整体阅读路线、长期继承与完整讨论过程由各自入口维护。

## 开始前确认范围

先读取目标仓库的阅读入口、唯一进度记录和当前步骤，定位本步已确认的函数与记录重点。尚未确认时，先与用户讨论准备读哪个函数、围绕它弄清什么、短期记忆准备保留什么；助手可提出候选及理由，确认后才展开源码或创建函数记忆。已有明确指令直接沿用，整理已发生的讨论或执行明确纠错不重复询问。

目录顺序、旧阅读历史和已经准备的讲解不代表本步范围已确认。这里确认的是要研究什么，不要求用户提前知道答案或先证明掌握。

## 记录单位与位置

```text
02-short-term-memory/
├── overview.md
└── functions/<源码相对路径>/<完整函数名>.md
```

以单个函数作为可定位、可复用的记录入口，保留真实源码目录及脚本名。**卡片按函数保存，阅读按当前问题和处理阶段推进。** `overview.md` 只保存函数索引、来源和状态；任务主线与跨组件调用关系放在步骤 README / scope。只创建本步实际需要的记录，不复制整个源码树。

| 当前需要解释的内容 | 放在哪里 |
| --- | --- |
| 有独立职责与输入输出，且本步需要单独理解或后续复用的函数 | 创建或更新该函数卡片；调用处链接它，保留进入和返回的交接 |
| 同一函数内共同完成一次准备、转换或状态更新的连续语句 | 作为父函数卡片内的一个处理阶段，连起来解释 |
| 只为理解当前入口服务的辅助函数 | 在入口卡片内保留真实名称、行号和必要解释；出现独立阅读问题时，再按确认的范围拆卡 |

例如对象字段更新、长度统计、读取模式参数可以共同构成“响应前准备”。其中的 `replace`、`len`、`dict.get` 不因各自是一次调用就必须单独建卡。

同一函数已有认识时，本步记录保留使它独立可读的已有内容，再补充本步的新认识或修正。首次接触、原始来源与明确未知不能因复制或整理而丢失；“最近认识更新”只随实际理解变化更新。

## 从长期记忆调取本步要用的函数

`02` 保存本步正在使用的函数记录，包括新读的函数和从 `03` 调取的旧函数。已确认本步需要阅读或回顾某个函数时，即使没有新认识，也把 `03` 中的完整卡片复制到本步 `02` 的同名源码路径；本步已有该卡时直接复用，避免覆盖本步补充。

- 保留原话、未知、首次接触、最近认识更新与原始来源，单独注明“本步调取”及来源快照。调取或补充调用场景不算个人认识更新。
- 对齐本次调用者、实参和返回位置，重算相对链接；scope、调用方与本步索引直接链接 `02` 中的卡片，读者在本步即可回看完整记录。
- `03` 继续保留进入本步时的累计快照。尚未实际用到、只是候选或深层依赖的旧函数仍留在 `03`，不因调取一张卡片就递归复制全部依赖。
- 下一步仍按 `03 + 02` 合并；按源码路径与符号合成一份完整记录，保留有效旧内容和本步补充，不把纯调取标为新增理解。

## 函数记录写什么

先打开用户明确指定的认可样例，按它的栏目名称、顺序和展示方式填写。基础样例是 [BaseAdapter._translate](../repo-reading-memory/references/base-adapter-translate.md)，[短期函数模板](../repo-reading-memory/references/short-term-memory-template.md)是它的占位版；二者共同规定成稿，不把样例仅当作内容素材。锚点函数另参照 [BaseAdapter._run_turn](references/base-adapter-run-turn.md)，在相同栏目内展开函数自身的编排与数据交接。跨环境/跨边界调度函数另参照 [ClaudeCodeHarness.launch_and_wait](references/claude-code-launch-and-wait.md)，在“本场景的输入与输出”中采用显式 ASCII 流转图，用双线框 `╔══╗` 严格划出本函数直接职责与下游协同背景（沙箱环境、后端服务）的分界。

| 内容 | 记录要求 |
| --- | --- |
| 开头定位 | 源码定位、首次接触、最近认识更新；复制或格式修正不改变认识时间 |
| LLM 整理：使用场合、具体内容与心智模型 | 依次写四项：使用场合、具体内容、建议构建的心智模型、调用代码；模型用 `>` 引用块，调用只留当前交接必需的几行 |
| 本场景的输入与输出 | 分开显示同一场景的输入与输出，保留所有相关输入、返回项和关键模式参数；注明缩减、节选与验证范围 |
| 我的直接表述（原话） | 逐字保留用户表述，节选及多次回答分别标明；尚无直接表述时如实注明 |
| 尚不清楚 | 保留已经暴露的疑问与尚未展开的实现 |
| 来源、验证与完整例子 | 使用折叠区集中保存固定版本、行号、样例来源、验证方式及原始步骤的讨论链接 |

函数以配置或输入分派不同路径、需要分清各类职责时，参考[分支图配合分类依据](references/branch-diagram-mental-model.md)：在第三项心智模型中放简短分支图，并说明每层按什么分类；标明下游边界与返回交接。顺序流程和状态变化继续选择适合它们的表达。

原话清楚时不再增加重复的归纳。源码解释不能代填个人理解；用户说“继续”、文件生成或静态核对成功，都不代表已经掌握。范围已确认后可以先建卡并注明尚无直接表述，不把复述作为保存记录的门槛。

“简短”通过压缩各栏文字和引用已有长解释实现，栏目和当前任务场景仍沿用认可样例。相邻函数的记录接住前一步的数据；保留当前问题必需的字段及所有相关返回项。输入改变后重新核对输出。区分当前函数返回值与调用者的后续结果，区分静态推导与实际执行。基类接口的示例要注明实际使用的具体实现。

**内部阶段写在“本场景的输入与输出”内。** LLM 四项继续概括整个函数的职责；追加局部问题时，沿用现有栏目，不把整张卡片改成只描述当前几行。简单函数直接展示输入输出；内部交接较多时，按以下顺序展开：

1. 保留整个函数在当前场景的输入、返回值与相关副作用。
2. 按实际执行顺序组织阶段，标出源码行号和当前展开处；需要时用简短阶段表或图辅助定位。只定位、尚未展开的阶段如实注明。
3. 当前阶段写清 **入口已有数据 → 实际语句 → 新增或更新的数据 → 下一次交接**。决定数据去向的赋值、计数、条件判断与函数调用一起解释，不能只按调用名称跳转。
4. 进入子函数前说明实参来自哪里、已完成哪些准备；返回后说明接住什么、父函数接下来用在哪里。已有子卡直接引用，父卡保留交接；两张卡片采用不同场景时明确区分，不能当成同一次运行的数据。

主样例沿用真实调用的模式参数。例如调用处启用了工具定义和 `tokenize=True`，主样例就保留这两项；为观察中间文本而改成 `False`、改用自定义模板的实验，放在补充说明中。缺少实际模型或 tokenizer 时，明确写出已核对的输出类型、用途和未取得的具体值，不用另一种模式的可运行结果替代原调用结果。

带读时提供局部材料，邀请用户说明当前理解，再根据回答聚焦一个关键区别。按实际发生的问答补充原话和未知；不要先给完整答案，再要求照着复述。完整问答和扩展讲解链接到原始 flow 或参考文件，不重复抄进函数记录。

## 锚点函数的组织方式

当一个函数是本步深入阅读的入口，并通过多个子函数完成整体职责时，参照用户已认可的 [BaseAdapter._run_turn 完整卡片](references/base-adapter-run-turn.md)。仍以这个函数为记录对象，先给出整个调用的场景输入、返回值和状态变化，再解释它怎样组织内部处理。

- 内部阶段放在“本场景的输入与输出”中，统一按 **阶段标题与源码范围 → 连续代码块 → 分条逻辑说明 → 子函数跳转表** 组织；没有需要展开的子函数时无需跳转表。
- 说明用 `-` 或编号逐条对应具体的数据、状态与交接关系。代码块保持连续，解释位于代码和跳转表之间；用户只要求解释分条时，不拆散代码、不删除表格或重排其他栏目。
- 跳转表写清“需要展开时进入哪里”和“读完回到这里，接着使用什么”。父卡解释自身的调用组合，子卡承接被调用函数的内部实现。
- 阶段数量按实际函数决定，不固定为样例中的三段。详细字段和辅助状态机制可按需折叠，主要输入输出与关键交接仍须直接可见；简单函数继续沿用基础样例。

scope 负责阅读目标、骨架和函数入口；函数卡片建立完整的单函数模型，并在实际调用处提供局部跳转；[task flow](../repo-reading-task-flow/SKILL.md) 在本步阅读后总结该 scope 内的整体配合，以 Step 003 为主要 reference。不要因 scope 或 task flow 中已有流程，就删去锚点函数自身的编排。问答与修正经过仍保存在 `04-flow.md` 或对应讨论中。

## 共用模型与引用入口

**共同记录已经完整覆盖某个具体实现的本轮场景时，具体实现直接引用共同记录，不另写重复的场景、输入输出和心智模型。**

- 具体实现文件开头直接链接共同记录，只保留继承或实现关系、源码定位、原始来源和已有认识时间。
- 函数索引直接指向共同记录，同时保留具体实现的定位入口。引用文件用于导航，不需要再填写完整函数模板。
- 继承关系、接口声明和具体执行体按源码如实说明。共同记录里的示例采用哪个实现，应能从内容或来源中辨认。
- 原有个人表述、未知和证据若不在共同记录中，保留可回查的原记录；有独有的新问题时，再按用户确认的范围补充具体实现的差异。

例如：当前 `BaseAdapter._translate` 记录已经完整展示 Anthropic 请求的转换场景，`AnthropicAdapter._translate` 只保留指向它的入口。这里共用的是场景解释，不把源码中的两个方法合并成一个函数。

## 保存与交接

保存前把**整张当前函数卡片**与认可样例并排核对，新建和修订都适用：栏目顺序是否一致，LLM 四项是否仍描述整个函数，当前场景和关键参数是否对应调用处，输入输出及当前阶段的交接是否完整。当前卡片若沿用旧格式，应在保留内容的基础上校正，不能只检查新增段落。

再核对原话、认识时间、未知、来源和引用入口；格式检查或代码片段能运行，不能替代这一步。形成过程链接包含原始步骤名，移动后仍能回到真正产生这段认识的讨论，不误指向新步骤。

本 skill 写入本步 `02`，不改写此前累计的 `03`，不重写旧步骤快照，也不因记忆已保存就推进学习进度。Step 0 的 `03` 初始为空；进入下一步时的 `03 + 02` 继承由[记忆总入口](../repo-reading-memory/SKILL.md#6-怎样更新和继承)处理。
