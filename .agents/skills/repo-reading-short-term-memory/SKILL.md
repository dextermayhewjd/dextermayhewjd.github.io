# 源码阅读：单函数短期记忆

负责本步 `02-short-term-memory/` 中的函数记录与索引。保存学习者实际表达的理解，并配上核对过的场景、调用代码、输入输出和 LLM 模型。整体阅读路线、长期继承与完整讨论过程由各自入口维护。

## 开始前确认范围

先读取目标仓库的阅读入口、唯一进度记录和当前步骤，定位本步已确认的函数与记录重点。尚未确认时，先与用户讨论准备读哪个函数、围绕它弄清什么、短期记忆准备保留什么；助手可提出候选及理由，确认后才展开源码或创建函数记忆。已有明确指令直接沿用，整理已发生的讨论或执行明确纠错不重复询问。

目录顺序、旧阅读历史和已经准备的讲解不代表本步范围已确认。这里确认的是要研究什么，不要求用户提前知道答案或先证明掌握。

## 记录单位与位置

```text
02-short-term-memory/
├── overview.md
└── functions/<源码相对路径>/<完整函数名>.md
```

以单个函数为记录单位，保留真实源码目录及脚本名。`overview.md` 只保存函数索引、来源和状态；任务主线与跨函数交接放在步骤 README / scope。只创建本步实际需要的记录，不复制整个源码树。

同一函数已有认识时，本步记录保留使它独立可读的已有内容，再补充本步的新认识或修正。首次接触、原始来源与明确未知不能因复制或整理而丢失；“最近认识更新”只随实际理解变化更新。

## 函数记录写什么

使用[短期函数模板](../repo-reading-memory/references/short-term-memory-template.md)，按以下顺序组织：

| 内容 | 记录要求 |
| --- | --- |
| 我的理解（原话） | 逐字保留用户对函数的表述，节选及多次回答分别标明；尚无直接表述时如实注明 |
| 使用场景与调用代码 | 简短说明当前任务、调用者与后续消费者，附几行真实调用 |
| Input → Output | 一组对应的小输入与当前函数的返回值或副作用，标明教学构造、缩减或输出节选 |
| LLM 补充模型 | 简短说明职责与边界，明确它是助手据源码提供的解释 |
| 尚不清楚 | 保留已经暴露的疑问与尚未展开的实现 |
| 来源 | 源码路径、符号、固定版本和行号，样例来源、验证方式及原始步骤的讨论链接 |

原话清楚时不再增加重复的归纳。源码解释不能代填个人理解；用户说“继续”、文件生成或静态核对成功，都不代表已经掌握。范围已确认后可以先建卡并注明尚无直接表述，不把复述作为保存记录的门槛。

默认使用短场景、少量调用代码和一组小输入输出；保留当前问题必需的字段及所有相关返回项，不为缩短而省掉一条输出。输入改变后重新核对输出。区分当前函数返回值与调用者的后续结果，区分静态推导与实际执行。基类接口的示例要注明实际使用的具体实现。

带读时提供局部材料，邀请用户说明当前理解，再根据回答聚焦一个关键区别。按实际发生的问答补充原话和未知；不要先给完整答案，再要求照着复述。完整问答和扩展讲解链接到原始 flow 或参考文件，不重复抄进函数记录。

## 共用模型与引用入口

**共同记录已经完整覆盖某个具体实现的本轮场景时，具体实现直接引用共同记录，不另写重复的场景、输入输出和心智模型。**

- 具体实现文件开头直接链接共同记录，只保留继承或实现关系、源码定位、原始来源和已有认识时间。
- 函数索引直接指向共同记录，同时保留具体实现的定位入口。引用文件用于导航，不需要再填写完整函数模板。
- 继承关系、接口声明和具体执行体按源码如实说明。共同记录里的示例采用哪个实现，应能从内容或来源中辨认。
- 原有个人表述、未知和证据若不在共同记录中，保留可回查的原记录；有独有的新问题时，再按用户确认的范围补充具体实现的差异。

例如：当前 `BaseAdapter._translate` 记录已经完整展示 Anthropic 请求的转换场景，`AnthropicAdapter._translate` 只保留指向它的入口。这里共用的是场景解释，不把源码中的两个方法合并成一个函数。

## 保存与交接

核对原话、来源、输入输出的对应关系，以及引用入口的目标。形成过程链接包含原始步骤名，移动后仍能回到真正产生这段认识的讨论，不误指向新步骤。

本 skill 写入本步 `02`，不改写此前累计的 `03`，不重写旧步骤快照，也不因记忆已保存就推进学习进度。Step 0 的 `03` 初始为空；进入下一步时的 `03 + 02` 继承由[记忆总入口](../repo-reading-memory/SKILL.md#6-怎样更新和继承)处理。
