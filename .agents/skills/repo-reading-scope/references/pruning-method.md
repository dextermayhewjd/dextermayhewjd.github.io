# 阅读方法 reference：先找指挥官，再剪枝

依据用户提供并确认的[代码阅读指南第一条](../../../../00-repo-reading/code-reading-guide.md#用户提供的准则原文)整理。这里把详细方法转为可执行的阅读步骤；完整原话继续保留在指南中。

## 一、先确定当前要解释的任务

将“理解整个项目”缩小为一个可跟随的任务，例如“一份代码任务怎样被执行并交回结果”。本轮先获得一条可定位、可继续展开的主线。

在项目入口或调用处确定范围。用户已选定某个局部问题时，就在该局部寻找组织流程的函数；不要每次重返训练入口或要求补齐所有启动代码。

## 二、找到指挥官函数（Orchestrator）

用户原方法强调：先找串联主流程的少数函数，不从文件第一行顺序通读所有辅助函数。

1. **用名称缩小候选。** `run`、`generate`、`execute`、`step`、`main` 通常值得优先查看，但名称和是否带下划线都不是结论。
2. **用职责确认。** 看它是否接收本任务、依次调用主要组件、处理组件之间的交接，并返回任务结果或产生主要副作用。
3. **分清主流程与工具函数。** 一个名为 `run` 的函数可能只执行 shell；另一个私有函数可能才组织完整任务。短包装入口可以继续定位到实际编排函数，并说明两者关系。
4. **保留够用的定位。** 记录文件、符号、固定版本或当前证据状态。后续读者能直接跳回源码即可，不列整仓函数清单。

原文中的“80% 是辅助函数”“整体轮廓 100% 建立”用于强调取舍，不作为统计结论、选择算法或掌握程度的证明。函数行号和接口以正在阅读的版本为准。

## 三、开启脑内过滤器：暂时忽略五类噪音代码

先看正常路径，再补当前问题需要的异常与边界。以下内容在第一遍通常折叠：

| 类别 | 识别线索 | 第一遍的处理 |
| --- | --- | --- |
| 1. 环境与配置解析 | `CONFIG = ...from_env()`、读取环境变量、构造默认参数 | 先说明必要条件已具备，把配置细节留到对应问题；配置决定执行哪个组件时仍需定位该组件 |
| 2. 前置安全检查（Guard Clauses） | `if not ...: return ...`、无效输入检查、提前退出 | 选定输入有效的正常路径，并用一句话说明必要前提 |
| 3. 日志与耗时统计（Telemetry） | `logger.info(...)`、`time.time()`、指标和诊断输出 | 从骨架中省去；诊断本身是本步目标时再展开 |
| 4. 超时与异常兜底（Error Handling） | `try/except`、超时上下文、失败诊断 | 先保留正常执行顺序，说明超时与异常暂未展开 |
| 5. 失败分支包装（Abort Wrappers） | `_abort_result(...)` 等失败结果封装 | 暂不跟进错误结果的构造过程 |

**按代码职责分类，不按关键词删除。**

- `if` 也可能决定业务分支，例如运行测试还是静态检查。应保留这项选择，或明确当前只讨论哪个分支。
- `async with` 也可能创建核心工作环境。保留环境创建、嵌套范围及调用顺序，不能因另有超时上下文就把全部上下文管理都折叠。
- 重试、回滚、取消或清理若正是用户的问题，就属于本轮主线；五类过滤不用于排除任务本身。

这里的“忽略”是暂缓阅读，在教学骨架中省略；不删除实际源码，也不宣称被省去的行为不重要。

## 四、画出真正干活的核心骨架

1. 从已确认的编排函数中保留组织当前任务的调用。
2. 沿真实顺序排放，保留作用域、等待关系、业务分支和返回结构。
3. 参数统一用 `...`；用短注释说明每项调用的用途。参数如何组装、字段如何转换，留到局部阅读时展示。
4. 标注这是教学裁剪，交代所选路径与省略范围。步骤数由真实任务决定，“七句”仅是 Coding Agent 样例的数量。
5. 写一句停止条件，例如“能说明任务依次经过哪些环节，以及每个环节的职责”。这不要求先掌握所有子函数的内部机制。

对照[紧凑的 Coding Agent 样例](coding-agent-scope.md)。样例保留 `reward, applied_cleanly` 的真实多返回值，也保留工作区内的缩进；省去调用参数和辅助流程。

## 五、顺藤摸瓜，追到能交接就返回

首轮先看骨架。需要解释其中某项时，从当前指挥官向下最多追两层：入口为第 0 层，直接子调用为第 1 层，子调用内部再一层为第 2 层。

进入子函数时带着具体问题，确认它的用途、输入、输出或副作用。弄清当前交接后返回调用处，继续原来的任务主线。更深的机制留作后续候选，由用户确认本轮是否转向。

这个深度限制用于控制一轮阅读的展开量；发现必要前置时先说明缺少哪项关系，不能把未懂的部分写成已经理解。
