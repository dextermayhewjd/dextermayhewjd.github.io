# 源码阅读：范围与核心骨架

把阅读目标落实为本步的入口、核心调用和停止位置，写入步骤层的 `01-scope.md`。采用用户确认的读法：先找指挥官函数，开启脑内过滤器，再按问题有限下钻。

## 职责与前置

先读目标仓库的阅读约定、项目入口、唯一进度记录和当前步骤。沿用已确认的目标、源码仓库与版本；已有阅读历史用于提醒，不代表当前已理解全部机制。

用户已经指定本步目标与范围时直接执行。范围尚未确定时，先小范围定位候选入口，说明选择理由，再与用户确认本步问题；候选与已确认范围分别标注。定位候选不要求预先掌握所有上游初始化。

本 skill 负责阅读范围与骨架。单函数的原话、输入输出和心智模型交给 [repo-reading-short-term-memory](../repo-reading-short-term-memory/SKILL.md)；累计继承交给 [repo-reading-memory](../repo-reading-memory/SKILL.md)。骨架中出现的函数仅表示主线位置，不自动创建函数记忆或标记掌握。

已有骨架后需要判断先深入哪个调用时，使用 [repo-reading-order](../repo-reading-order/SKILL.md)比较候选；确认本轮问题后再用本 skill 确定 scope。

## 1. 找出指挥官函数

从当前任务反查入口，优先查看 `run`、`generate`、`execute`、`step`、`main` 等候选；以实际职责判断：它是否串联本任务的准备、执行与结果交接？

名称只是线索。私有函数也可能负责主流程，公共函数也可能只是包装或小工具。读取定义与必要调用者，确认返回值和主要副作用，再决定本步入口。只负责局部字符串、日志或命令执行的函数不能因名字像入口就被选中。

## 2. 开启脑内过滤器

第一遍提取正常路径，按以下五类暂时折叠代码。详细判别方法见 [剪枝方法 reference](references/pruning-method.md)。

| 暂时折叠的类别 | 常见内容 |
| --- | --- |
| 环境与配置解析 | 环境变量、配置对象、参数准备 |
| 前置检查（Guard Clauses） | 无效输入检查、缺少条件时的提前返回 |
| 日志与耗时统计（Telemetry） | 日志、计时、指标和诊断输出 |
| 超时与异常兜底（Error Handling） | 超时包装、异常捕获、故障诊断 |
| 失败分支包装（Abort Wrappers） | 将失败原因封装成返回结果的调用 |

这些分类用于阅读裁剪。若条件选择不同业务路径，保留分支关系，或明确本步只看哪个分支；若配置决定实际执行对象，保留足够信息定位它。省略的清理、异常与必要前提用一句话标明，源码本身保持完整。

## 3. 提取核心骨架，有限下钻

骨架保留真实函数名、调用顺序、关键返回值、`await` 和必要的上下文嵌套。**调用参数统一写成 `...`**，每行用短注释说明职责；具体参数留到对应函数展开时查看。只在本轮问题明确针对某个参数或数据交接时，展示有关的少量参数。

按真实返回结构写赋值；没有返回值的调用不新增变量，多返回值不冒写成单一结果。不要为了凑成七步合并不相干的调用，也不要把示意包装函数当作源码入口。标明“教学裁剪”，注明选定路径和省略范围。

需要下钻时，从指挥官函数向下最多追两层；弄清子函数的用途、输入输出及返回位置后，回到主线。更深的问题记录为后续候选，不因看到调用就连续追完全部实现。

### 按需分支：局部阅读导航

**本步已确认要展开整体骨架中的某个调用时**，阅读 [局部导航 reference](references/local-call-context.md)，在 scope 的第 3 部分依次交代：

1. **整体位置**：保留已有完整核心骨架，包括全部业务环节与必要嵌套，在对应调用处标出本步；其余环节保留简短职责，只作定位。
2. **局部骨架**：从当前入口裁剪正常路径，用真实调用、短注释和源码行号说明内部怎样交接；保留读者需要看清的返回、交付与退出时机。
3. **阅读导航**：指出先看哪里、各处要弄清什么、读到什么程度，以及返回哪一行继续。已有卡片直接链接；尚未阅读的函数先链接源码，不预建卡片或填写学习结论。

**调用对象、关键输入或实际实现尚不清楚时**，在局部骨架前补最少的来源关系，例如“取得对象 → 调用方法”或“取得编号 → 传入当前调用”。只回查缺失关系，不因出现对象方法就追完构造和初始化。

**只做整体概览时**，保持整体骨架与停止位置，不新增局部展开。**局部调用简单、来源已清楚时**，用几行代码和一句返回说明即可，不强行增加调用树或跳转表。

“先建 scope、暂不填写具体函数”表示暂缓函数卡片；scope 仍需保留已确认范围内的局部导航。若用户明确要求只定位、不展开内部，则按该边界保留调用位置和后续问题。

### 按需分支：阅读路径图与回查

**观察点较多，或阅读中需要回查并返回主线时**，参考下面两份用户已认可的完整 scope。两份都已包含整体定位、局部骨架、阅读图与导航表；按当前问题选择参考，不需要据此改写原步骤。

| 完整样例 | 重点参考什么 |
| --- | --- |
| [Step 001：一次模型请求](references/step-001-reading-path.md) | 沿局部编排的数据主线阅读，中途回看追踪包装，辅助函数从所属分支进入后返回 |
| [Step 002：运行统计与补丁提取](references/step-002-reading-path.md) | 从结果读取回查输入的写入、配置与初始化，再返回原调用、继续下一项结果 |

- 图表达“先读哪里 → 按需回查 → 回到哪里”，辅助函数放在所属分支下；表与图编号一致，补上卡片或源码入口、当前问题、阅读深度和返回位置。
- 局部骨架保留真实执行顺序；阅读图标明回看、跨请求关联等阅读关系。阅读导航在 scope 维护，实际追问与修正留在 04-flow；task flow 总结执行与数据交接，并引用 scope 的导航。
- 新步骤先保留已确认的入口，回查分支随问题和范围确认逐步补全。样例的函数、观察点数量和已读状态只属于原步骤，不能直接套作下一步的清单。

## 4. 生成三段 scope

| 部分 | 要回答的问题 |
| --- | --- |
| `1. 阅读目标` | 总目标是什么？本步先看清哪条任务流程或哪项交接？ |
| `2. 找到指挥官函数` | 从哪个真实文件与符号进入？为什么它适合组织当前任务？ |
| `3. 给出真正干活的核心骨架` | 正常路径有哪些核心调用？局部阅读时，从哪里展开、如何回到主线？本步读到哪里停？ |

目标写一两句话；入口附必要源码定位与版本；骨架先展示紧凑代码，再用一句话写明停止位置。整体目标可以是“理解 Coding Agent”，本步目标需缩小为本次能够看清的流程。三个部分之内交代前提和边界，不另堆一套重复栏目。

本轮只讨论格式时，结论保存在对应格式讨论中；实际开始阅读后，再按仓库约定接续步骤与进度。保留旧步骤当时的格式、来源和未知。

## Reference 与完成检查

- [剪枝方法](references/pruning-method.md)：执行本方法时阅读，包含指挥官判断、五类过滤、下钻与常见误判。
- [Coding Agent scope 样例](references/coding-agent-scope.md)：需要对照三段格式时阅读；这是固定源码的样例，不预设其他仓库也从 `generate` 开始。
- [局部导航 reference](references/local-call-context.md)：本步展开某个核心调用，或需补调用对象、输入与实现来路时阅读；示范整体定位、局部骨架、阅读深度和返回位置。
- 完整局部 scope 样例：[Step 001](references/step-001-reading-path.md)与 [Step 002](references/step-002-reading-path.md)。两份均按已认可的正文保存，分别展示沿编排主线阅读与回查输入来源；共同参考阅读图、定位表和实际执行骨架的分工。

交付前核对：入口确实串联当前任务；核心调用有源码依据；参数展示符合本步问题；业务分支和返回结构没有被剪错；局部阅读同时保留整体位置与可跟随的局部导航；停止位置明确。文档生成或源码核对成功，不作为学习者已掌握的证据。
