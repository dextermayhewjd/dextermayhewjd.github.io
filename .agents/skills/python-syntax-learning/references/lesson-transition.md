# 从已学内容连接到新问题

适用于为新课定位前置知识、帮助读者回想旧知识并理解本课问题的情况。若尚未说明新机制解决什么，先参考 [新机制如何承接旧方案](introducing-new-mechanisms.md)。

## 1. 先找真正复用的旧知识

课程排列顺序与知识依赖分别判断。检查本课例子用到了哪些已学行为，以及本课的问题接续了哪个旧问题；相关知识可能在更早的课里，也可能分布在几节课中。引用前核对旧课确实讲过该行为，不能仅因出现过同名 API 就认定已学会。

例如，资源准备与清理的例子复用了先前的 `try/finally`。即使前一课讲的是 `Event` 通知，开头也应回接实际讲过清理行为的旧课。翻页导航仍可指向前一课，它不代表概念依赖。

只选解释本课所需的关键连接，不把全部依赖列成 API 清单。没有可回接的旧课时，交代必要基础；如果基础尚未学过，补足或确认学习起点，不编造“之前已经学过”。

## 2. 开头单独放“与已学内容的连接”

连接说明保持简短、默认可见，放在主例子之前。分清以下两项：

1. **复用的旧知识：** 链接真正相关的旧课或小节，用一句具体行为帮助回忆，说明本课会怎样继续用它。
2. **本课新增的问题：** 写出新增的条件、观察角度或管理责任，让读者知道接下来要解决什么。

例如：

> **与已学内容的连接**
>
> **复用的旧知识：** 在先前的任务取消例子中，任务通过已进入的 `finally` 完成清理。这里继续把关闭资源的代码放在 `finally` 中。
>
> **本课新增的问题：** 一次资源使用包含准备、使用和关闭三个阶段。这三段代码分别应该放在哪里？

实际页面应给“先前的任务取消例子”补上对应链接。连接说明负责唤起记忆，完整执行过程留给后文，不在这里重讲整节旧课。

需要比较旧方案与新要求时，再让读者尝试旧法：提出可判断的问题，观察旧写法在新条件下的行为。问题先落在要完成的工作上，随后再引入解法；复用旧语法研究新问题的课，不必虚构旧方案的不足或强行增加新 API。

## 6. 核对呈现和边界

1. 主例子前有独立可见的连接说明，让读者知道“复用了什么旧知识、本课继续研究什么”；只有课号或名称不算完成连接。相关旧课须经核对，不能仅用上一课凑过渡。
2. 保留前文有效的例子和讲解，优先修改过渡与问题描述，不因改进开头而重写整课。
3. 检查网页中实际显示和复制出的 Python 代码，保留缩进、换行和脚本入口；完整独立脚本按前文约定使用 `if __name__ == "__main__":`。
4. 错误尝试需要核对实际失败原因；正常路径的例子只能支持正常路径的结论。
