# 新机制如何承接旧方案

旧方案：先用 `create_task` 安排任务，再分别 `await`。这已经可以让任务并发推进；各个 `await` 正常完成后，也可以等完所有记录的任务。

新增的问题：哪些任务属于同一段工作，谁负责在离开这一段代码前等待和收尾？新增任务时，调用方要把它也纳入等待；如果中途返回或某个 `await` 抛出异常，写在后面的等待可能没有执行。

按这个问题引入 TaskGroup：通过 `group.create_task` 登记相关任务，把管理责任绑定到明确的作用域。正常退出时等待组内任务结束；异常退出涉及取消和清理，可以在后续单元解释。

讲解时区分以下几点：

1. 不把旧方案说成“不能并发”或“不能等完任务”；新机制改变的是管理方式与责任边界。
2. “能否把任务交给一个组”只是换一种语法的提议，还需要先说明为什么希望建立这个组。
3. 若主例子只演示正常退出，结论也限定于这个观察；提出提前返回和异常问题，不等于已经演示或验证了所有退出分支。

同样的判断可以迁移到其他 Python 机制。例如从 `try/finally` 引入 `with` 时，先承认旧写法能够清理资源，再说明新需求是把进入和退出规则封装成可复用的作用域协议。
