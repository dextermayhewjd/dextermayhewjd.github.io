## 2 转换函数分成两个工作部分

**执行逻辑：** `_translate()` 分别转换消息与工具定义，然后将两份结果一起返回。

**函数名：** `AnthropicAdapter._translate()`。

**源码：** `slime/agent/adapters/anthropic.py:58`，下面是该函数的完整实现。

```python
def _translate(self, body: dict) -> tuple[list[dict], list[dict] | None]:
    translated = _translate_messages(body.get("messages") or [], body.get("system"))
    tools_schema = _tools_to_chat_tools(body.get("tools"))
    return translated, tools_schema
```

| 工作部分 | 输入 | 输出 |
| --- | --- | --- |
| `_translate_messages()` | `messages`、顶层 `system` | `translated` |
| `_tools_to_chat_tools()` | 顶层 `tools` | `tools_schema` |

## 3 展开消息转换

**执行逻辑：** 先放入顶层系统指令，再按输入消息顺序处理每条消息，根据角色选择相应分支。

**函数名：** `_translate_messages()`。

| 定义位置 | 调用位置 |
| --- | --- |
| `slime/agent/adapters/anthropic.py:81` | `slime/agent/adapters/anthropic.py:59` |

### 3.1 顶层系统指令

**执行逻辑：** 将顶层 `system` 内容转换成文本，放到结果列表开头。

**参与函数：** `_translate_messages()`、`flatten_content()`。

**执行位置：** `slime/agent/adapters/anthropic.py:84`、`slime/agent/adapters/anthropic.py:85`。

**输出：** `{"role": "system", "content": ...}`。

### 3.2 用户文本和工具结果

**执行逻辑：** 按用户消息中的块顺序处理；文本块成为用户消息，工具结果块成为工具消息，其内容按需展开为文本。

**参与函数：** `_translate_messages()`、`flatten_content()`。

**执行位置：** 用户分支从 `slime/agent/adapters/anthropic.py:90` 开始；工具结果分支位于 `slime/agent/adapters/anthropic.py:93`，文本分支位于 `slime/agent/adapters/anthropic.py:95`。

**输出：** `role: user` 或 `role: tool` 的消息。

### 3.3 助手正文 推理内容和工具调用

**执行逻辑：** 遍历助手内容块，分别收集正文、推理内容和工具调用，然后放进同一条助手消息的对应字段。

**参与函数：** `_translate_messages()`、`tool_call_dict()`。

**执行位置：** 助手分支从 `slime/agent/adapters/anthropic.py:99` 开始；转换工具调用位于 `slime/agent/adapters/anthropic.py:111`；构造并填充消息从 `slime/agent/adapters/anthropic.py:112` 开始。

**输出：** `role: assistant` 的消息，包含 `content`，并按内容增加 `reasoning_content` 和 `tool_calls`。

## 6 将结果交回 Slime Core

**执行逻辑：** `AnthropicAdapter._translate()` 返回两个值。`BaseAdapter._run_turn()` 分别赋值给 `translated` 和 `tools_schema`，完成动作 2 的数据交接。

| 函数名 | 具体位置 |
| --- | --- |
| `AnthropicAdapter._translate()` 返回结果 | `slime/agent/adapters/anthropic.py:61` |
| `BaseAdapter._run_turn()` 接收结果 | `slime/agent/adapters/common.py:341` |

返回和接收发生在同一个适配器对象的函数调用中。下一行 `slime/agent/adapters/common.py:342` 使用这两份数据准备模型输入；这一步的展开见 [Slime Core 完整请求流程](<../Slime Core 完整请求流程.md>)。

图中 Slime Core 的 `TrajectoryManager` 在后续生成结果处理时保存轨迹；本次交接的直接接收者是共享的 `_run_turn()`。
