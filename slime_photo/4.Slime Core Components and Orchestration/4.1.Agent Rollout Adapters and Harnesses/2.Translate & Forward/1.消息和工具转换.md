# 动作 2 消息和工具转换

[返回最小心智模型](README.md) · [下一篇 主路径和源码函数](2.主路径和源码函数.md)

从一条普通用户消息开始，每次增加一种内容。先观察输入和输出的变化，函数名和行号在下一篇逐项展开。

## 1 普通文本

```json
{
  "messages": [
    {
      "role": "user",
      "content": [
        {
          "type": "text",
          "text": "你好"
        }
      ]
    }
  ]
}
```

转换后，`translated` 为：

```json
[
  {
    "role": "user",
    "content": "你好"
  }
]
```

`tools_schema` 为 `None`。文本内容仍是“你好”，变化的是它的表示形式。

## 2 增加系统指令

在上一例的顶层请求里增加：

```json
{
  "system": "你是代码助手。"
}
```

转换后的消息列表变为：

```json
[
  {
    "role": "system",
    "content": "你是代码助手。"
  },
  {
    "role": "user",
    "content": "你好"
  }
]
```

顶层 `system` 被放到消息列表开头。工具定义仍为 `None`。

## 3 增加助手正文和推理内容

请求中的一条助手消息：

```json
{
  "role": "assistant",
  "content": [
    {
      "type": "thinking",
      "thinking": "先判断问题。"
    },
    {
      "type": "text",
      "text": "你好！"
    }
  ]
}
```

转换后：

```json
{
  "role": "assistant",
  "content": "你好！",
  "reasoning_content": "先判断问题。"
}
```

正文进入 `content`，推理内容进入 `reasoning_content`，两者保存在同一条助手消息的不同字段中。

## 4 增加工具定义

请求可以通过顶层 `tools` 声明可用工具：

```json
[
  {
    "name": "read_file",
    "description": "读取文件",
    "input_schema": {
      "type": "object",
      "properties": {
        "path": {
          "type": "string"
        }
      }
    }
  }
]
```

转换后的 `tools_schema`：

```json
[
  {
    "type": "function",
    "function": {
      "name": "read_file",
      "description": "读取文件",
      "parameters": {
        "type": "object",
        "properties": {
          "path": {
            "type": "string"
          }
        }
      }
    }
  }
]
```

`input_schema` 成为 `function.parameters`，名称和说明也放进 `function`。工具定义描述可用工具，这一步只转换定义。

## 5 增加已经发生的工具调用

请求的历史里可以包含助手发出的工具调用：

```json
{
  "role": "assistant",
  "content": [
    {
      "type": "text",
      "text": "我先读取文件。"
    },
    {
      "type": "tool_use",
      "id": "toolu_demo",
      "name": "read_file",
      "input": {
        "path": "README.md"
      }
    }
  ]
}
```

转换后：

```json
{
  "role": "assistant",
  "content": "我先读取文件。",
  "tool_calls": [
    {
      "type": "function",
      "function": {
        "name": "read_file",
        "arguments": {
          "path": "README.md"
        }
      }
    }
  ]
}
```

`tool_use` 成为 `tool_calls`，`input` 成为 `function.arguments`，参数保留为字典。用于客户端协议的 `id` 没有进入规范化工具调用。

这一步整理历史中的调用记录；`read_file` 的执行由客户端 Agent 处理。

## 6 增加工具执行结果

工具结果在 Anthropic 格式中放在用户消息的内容块里：

```json
{
  "role": "user",
  "content": [
    {
      "type": "tool_result",
      "tool_use_id": "toolu_demo",
      "content": [
        {
          "type": "text",
          "text": "# Demo"
        }
      ]
    },
    {
      "type": "text",
      "text": "概括内容。"
    }
  ]
}
```

转换后，得到两条消息：

```json
[
  {
    "role": "tool",
    "content": "# Demo"
  },
  {
    "role": "user",
    "content": "概括内容。"
  }
]
```

`tool_result` 转换为 `role: tool` 的消息，后面的普通文本转换为 `role: user` 的消息，两者按原块顺序展开。`tool_use_id` 没有进入转换后的消息。

## 7 一条消息包含多个文本块

```json
{
  "role": "user",
  "content": [
    {
      "type": "text",
      "text": "第一段"
    },
    {
      "type": "text",
      "text": "第二段"
    }
  ]
}
```

转换后：

```json
[
  {
    "role": "user",
    "content": "第一段"
  },
  {
    "role": "user",
    "content": "第二段"
  }
]
```

Anthropic 的一条用户消息可以展开成多条规范化消息。需要观察的是消息内容和顺序，不能假定输入与输出消息数量总是相同。

## 8 把这些变化放回完整请求

下面是前面各部分组成的一次请求：系统指令、用户问题、助手工具调用、工具结果、工具定义，以及采样字段。

输入 `body`：

```json
{
  "system": "你是代码助手。",
  "messages": [
    {
      "role": "user",
      "content": [
        {
          "type": "text",
          "text": "读取 README.md。"
        }
      ]
    },
    {
      "role": "assistant",
      "content": [
        {
          "type": "text",
          "text": "我先读取文件。"
        },
        {
          "type": "tool_use",
          "id": "toolu_demo",
          "name": "read_file",
          "input": {
            "path": "README.md"
          }
        }
      ]
    },
    {
      "role": "user",
      "content": [
        {
          "type": "tool_result",
          "tool_use_id": "toolu_demo",
          "content": [
            {
              "type": "text",
              "text": "# Demo"
            }
          ]
        },
        {
          "type": "text",
          "text": "概括内容。"
        }
      ]
    }
  ],
  "tools": [
    {
      "name": "read_file",
      "description": "读取文件",
      "input_schema": {
        "type": "object",
        "properties": {
          "path": {
            "type": "string"
          }
        }
      }
    }
  ],
  "max_tokens": 128
}
```

输出 `translated`：

```json
[
  {
    "role": "system",
    "content": "你是代码助手。"
  },
  {
    "role": "user",
    "content": "读取 README.md。"
  },
  {
    "role": "assistant",
    "content": "我先读取文件。",
    "tool_calls": [
      {
        "type": "function",
        "function": {
          "name": "read_file",
          "arguments": {
            "path": "README.md"
          }
        }
      }
    ]
  },
  {
    "role": "tool",
    "content": "# Demo"
  },
  {
    "role": "user",
    "content": "概括内容。"
  }
]
```

输出 `tools_schema`：

```json
[
  {
    "type": "function",
    "function": {
      "name": "read_file",
      "description": "读取文件",
      "parameters": {
        "type": "object",
        "properties": {
          "path": {
            "type": "string"
          }
        }
      }
    }
  }
]
```

转换函数将这两份结果作为 `(translated, tools_schema)` 返回。`max_tokens` 等采样字段仍保留在原 `body` 中，后续流程会读取它们。
