## 2 E2BSandbox 怎样创建远端环境

**函数：** `E2BSandbox.__aenter__()`，`slime/agent/sandbox.py:281`。

| 输入或配置 | 怎样使用 |
| --- | --- |
| `image` | 作为镜像路由元数据的值 |
| `image_metadata_key` | 决定镜像值写在 metadata 的哪个键中，未设置则抛错 |
| `size` | 非空时增加 size 元数据，键名根据镜像键的前缀构造 |
| `self.timeout` | 传给创建 API 的沙箱生命周期参数 |

创建语句位于 `slime/agent/sandbox.py:298`：

```python
self._sb = await self._rpc_retry("create", lambda: AsyncSandbox.create(timeout=self.timeout, metadata=md))
self.sandbox_id = self._sb.sandbox_id
return self
```

`self._sb` 是 E2B SDK 提供的远端沙箱操作对象；返回的 `self` 是 Slime 的包装对象，随后作为 `sb` 交给 Harness。具体镜像路由由部署中的 E2B 网关解释。

## 4 区分三层重试

| 重试层 | 处理什么 | 本版本的默认行为 |
| --- | --- | --- |
| `E2BSandbox._rpc_retry()` | 被识别为瞬时故障的传输异常 | 默认最多尝试 6 次，可配置；非幂等操作不重放 |
| `install_npm_cli()` | 安装命令返回非零退出码或等待超时 | 最多尝试 3 次安装，每次等待预算 300 秒；失败后抛错 |
| `boot_agent_sandbox()` | 创建或安装阶段抛出的异常 | 默认最多尝试 2 次，可配置；为下一次尝试重新创建候选沙箱 |

`install_npm_cli()` 的循环不捕获任意传输异常；这类异常若从底层继续抛出，会进入外层启动重试。

**传输失败与命令失败走不同处理。**例如 SDK 抛出 `CommandExitException` 时，`E2BSandbox.exec()` 按 `check` 返回退出码或转换为 `RuntimeError`；`:335`–`:340` 是这个分支。

`_rpc_retry()` 根据异常类型和部分消息判断是否重试。它对 `SandboxException` 的 `does not exist` / `STOPPED state` 判为不可重试；可重试异常且允许重放时，在后续尝试前重置连接池并退避。

### 为什么后台启动也标记 `idempotent=True`？

`exec_and_wait()` 的后台启动命令中有这一段：

```bash
mkdir /tmp/.run.spawned 2>/dev/null || exit 0
```

第一次成功创建锁目录才继续启动进程；同一次启动请求因传输失败被重放时，已有锁目录会让命令提前退出，避免重复启动。旧状态清理放在启动之前的独立 RPC 中；下一次逻辑调用会重新清理。

源码注释明确要求：**同一沙箱中不能让两个使用相同 tag 的 `exec_and_wait()` 同时运行。**它们会使用相同脚本、锁、日志和结束标记，防重锁只处理同一次启动的传输重放。

## 5 三种时间限制各管哪一层

| 时间限制 | 所在位置 | 达到限制后的含义 |
| --- | --- | --- |
| 沙箱生命周期 | `E2BSandbox.__init__()` / 创建 API | 配置远端沙箱的存活时间，默认 3600 秒 |
| 单次操作超时 | `sb.exec(timeout=...)` | 限制这一条 SDK 命令请求，具体超时异常由 SDK 产生 |
| Agent 等待预算 | `exec_and_wait(time_budget_sec=...)` | 轮询预算用尽时返回 `EXIT_TIME_BUDGET_EXCEEDED = -1` |

`_await_done_marker()` 用期限控制循环，每轮先等待 5 秒再执行一次检查；这不是精确的硬截止时间。**返回 `-1` 的代码本身没有杀掉后台 CLI。**之后离开沙箱上下文时，外层会尝试销毁沙箱。

外层 `generate()` 还使用 `asyncio.timeout(CONFIG.rollout_guard_sec)` 保护整个 rollout。这是任务级限制，定位见[动作 4 的生命周期](<../4.Launch Agent/3.会话入口和生命周期.md>)。

## 6 文件读取失败怎样表现

`E2BSandbox.read_file()` 在 `slime/agent/sandbox.py:380` 定义。SDK 读取在 `_rpc_retry()` 中尝试；该函数捕获继续抛出的 `Exception` 并返回 `""`。

因此空字符串可能表示文件为空，也可能表示读取失败。这个接口没有同时返回退出码或错误说明。前面文件操作例子的返回内容以读取成功为前提。

## 7 结束或失败时谁释放资源

| 场景 | 清理行为 |
| --- | --- |
| 已创建候选沙箱，但 CLI 安装抛出异常 | `boot_agent_sandbox()` 内层捕获 `BaseException`，先调用候选对象的 `__aexit__()` 再重新抛出 |
| 正常完成任务并收集 diff | 离开 `boot_agent_sandbox()` 上下文，在 `finally` 调用 `__aexit__()` |
| `yield sb` 后任务抛错或被取消 | 同一个 `finally` 负责沙箱退出 |
| E2B 的销毁调用抛出普通异常 | `E2BSandbox.__aexit__()` 记录 warning，不继续抛出该异常 |

`E2BSandbox.__aexit__()` 定义于 `slime/agent/sandbox.py:302`，`:305` 调用 `self._sb.kill()`。该实现尝试销毁远端沙箱；不能把执行了清理函数直接等同于销毁已成功。
