# 动作 5 命令和文件操作

[返回最小心智模型](README.md) · [下一篇 主路径和源码函数](2.主路径和源码函数.md)

从一条短命令开始，每次增加一种环境操作。教学例子假设 `sb` 已创建；目录、会话 ID 和输出均为示意值。函数名和源码位置在下一篇展开。

## 1 执行一条短命令

```python
exit_code, stdout, stderr = await sb.exec(
    "printf 'ready\\n'",
    user="root",
    timeout=15,
    check=True,
)
```

预期返回结构：

```python
(0, "ready\n", "")
```

| 字段 | 含义 |
| --- | --- |
| `exit_code` | 命令的退出码，`0` 表示该命令成功结束 |
| `stdout` | 命令的标准输出 |
| `stderr` | 命令的标准错误输出 |

`timeout` 是这次执行请求的超时参数。CLI 整个任务的等待预算另由长命令辅助函数处理。

## 2 增加 Agent 用户与工作目录权限

Harness 运行任务前的真实调用：

```python
await ensure_agent_user(sb, "/workspace/demo")
```

传入沙箱的命令展开后是：

```bash
id agent >/dev/null 2>&1 || useradd -m -s /bin/bash agent && chown -R agent:agent /home/agent /workspace/demo && git config --system --add safe.directory '*' && id agent
```

| 操作 | 环境中的变化 |
| --- | --- |
| 检查 `id agent`，必要时 `useradd` | 确认 `agent` 用户存在 |
| `chown -R` | 把 `/home/agent` 与工作目录交给 `agent` 用户 |
| `git config --system --add safe.directory '*'` | 在沙箱中设置 Git 安全目录配置 |
| 最后执行 `id agent` | 检查用户状态，输出仍由 `sb.exec()` 返回 |

该函数以 `root` 执行这些准备工作，之后 CLI 以 `agent` 运行。调用方没有接收最后的输出，成功时 `ensure_agent_user()` 返回 `None`。

这一步使用已有工作目录；题目文件和仓库内容由调用方提前准备。

## 3 增加 CLI 配置文件

用户与权限准备好后，`BaseHarness.run()` 调用所选子类的：

```python
await self.write_config(sb, ctx)
```

以 Claude Code 为例，写入的 JSON 内容是：

```json
{
  "hasCompletedOnboarding": true,
  "bypassPermissionsModeAccepted": true
}
```

这份内容写到两个位置：

```text
/home/agent/.claude.json
/home/agent/.claude/settings.json
```

实际实现经 `sb.exec()` 执行 `mkdir`、`echo | tee` 与 `chown`。这里的“写配置”通过命令完成。

换成 Codex，`write_config()` 写的是 `/home/agent/.codex/config.toml`。假设模型入口为 `http://192.0.2.10:18001`，内容为：

```toml
model = "slime-actor"
model_provider = "slime"

[model_providers.slime]
name = "slime"
base_url = "http://192.0.2.10:18001/v1"
env_key = "OPENAI_API_KEY"
wire_api = "chat"
```

该实现先在宿主机编码为 Base64，再经沙箱命令解码写入文件，以处理 shell 引号。两种 Harness 都把配置文件的所有权交给 `agent`。

此时的成果是沙箱中的配置文件已就位；`write_config()` 返回 `None`。

## 4 增加直接文件写入与读取

Sandbox 也提供独立的文件接口。以下是教学例子：

```python
await sb.write_file(
    "/workspace/demo/task.txt",
    "Read README.md.\n",
    user="agent",
)
text = await sb.read_file("/workspace/demo/task.txt", user="agent")
```

写入成功时返回 `None`，读取成功时 `text` 为：

```python
"Read README.md.\n"
```

| 写入内容的类型 | `E2BSandbox.write_file()` 怎样处理 |
| --- | --- |
| `str` | 把文本交给 E2B 的 `files.write()` |
| `bytes` | 用 `io.BytesIO` 包装后上传 |
| `Path` | 打开宿主机文件，上传它的内容到指定沙箱路径 |

例如 `Path("/tmp/cli.tgz")` 表示宿主机上的文件，`"/tmp/harness-cli.tgz"` 是沙箱中的目标位置。相同的 `/tmp` 字样不代表同一个文件系统。

真实安装流程用这个接口上传 Node 运行时和 CLI 安装包；真实运行流程用它写启动脚本。`read_file()` 在该版本中会把读取异常转换成空字符串，详见第三篇。

## 5 增加启动环境变量

配置之后，Harness 组成启动命令与 `env`，交给公共 `run_agent()`。Claude Code 分支的部分环境如下：

```python
{
    "ANTHROPIC_BASE_URL": "http://192.0.2.10:18001",
    "ANTHROPIC_AUTH_TOKEN": "cagent-demo-0-0",
    "ANTHROPIC_MODEL": "slime-actor",
}
```

这里展示三个相关字段，实际分支还会加入固定环境变量和可选覆盖。`env` 最终随后台启动那次 `sb.exec()` 传入 E2B SDK 的 `envs` 参数，供 CLI 进程使用。

| 启动信息 | 去向 |
| --- | --- |
| `start_cmd` | 写进启动脚本，成为要执行的 CLI 命令 |
| `workdir` | 脚本开头执行 `cd` |
| `user="agent"` | 执行脚本使用的沙箱用户 |
| `env` | 随启动 RPC 传入进程环境 |

地址和会话 ID 如何接回 Adapter，见[动作 4](<../4.Launch Agent/1.启动参数和模型入口.md>)。本章只追踪这些配置怎样进入沙箱进程。

## 6 从短命令增加到长时间运行

真实 Agent 可能运行很久。公共 `run_agent()` 使用 `exec_and_wait()`，让一次长任务通过短操作完成启动和等待。

下面用 `cmd="printf 'finished\\n'"` 展示同一个机制，设 `workdir="/workspace/demo"`、`user="agent"`、`tag="run"`。生成的 `/tmp/.run.sh` 为：

```bash
#!/bin/bash
cd /workspace/demo
export HOME=/home/agent
printf 'finished\n'
echo $? > /tmp/.run.done
```

`HOME` 是现有源码在沙箱启动脚本中设置的进程环境变量。实际 Agent 运行时，脚本中这条 `printf` 换成所选 CLI 的启动命令。

| 顺序 | 沙箱操作 | 此时得到什么 |
| --- | --- | --- |
| 1 | `write_file()` 写脚本 | `/tmp/.run.sh` |
| 2 | `exec()` 清理上次同 tag 的状态 | 移除旧锁、旧日志与退出标记 |
| 3 | `exec()` 执行带 `mkdir` 防重的 `setsid bash` | 后台启动脚本，输出重定向到日志 |
| 4 | 每隔 5 秒调用 `exec()` 检查并读取标记 | 得到 CLI 退出码，或预算耗尽返回 `-1` |

实际 `run_agent()` 指定的日志文件是：

```text
/workspace/demo/.harness/trajectory.jsonl
```

它保存 CLI 的 stdout/stderr。日志格式取决于 CLI 的输出配置；文件名中的 `trajectory` 不代表这里保存了 TrajectoryManager 的训练样本。

`exec_and_wait()` 返回 `(exit_code, output)`。`run_agent()` 使用 `want_output=False`，丢弃辅助输出，把整数退出码交回 Harness；失败时辅助函数仍会读取日志尾部，但 `run_agent()` 没有使用它。

现在可以对应[主路径和源码函数](2.主路径和源码函数.md)。
