## 2 准备用户的辅助函数真正提交命令

**执行逻辑：** 用 root 权限确认或创建用户，调整用户目录与工作目录权限，配置 Git。

**函数名：** `ensure_agent_user()`。

| 定义位置 | 调用位置 | 提交命令位置 |
| --- | --- | --- |
| `slime/agent/sandbox.py:390` | `slime/agent/harness/common.py:97` | `slime/agent/sandbox.py:392` |

完整实现：

```python
async def ensure_agent_user(sb: Sandbox, workdir: str) -> None:
    """Create the unprivileged 'agent' user that owns workdir + can git diff."""
    await sb.exec(
        f"id agent >/dev/null 2>&1 || useradd -m -s /bin/bash agent && "
        f"chown -R agent:agent /home/agent {workdir} && "
        f"git config --system --add safe.directory '*' && id agent",
        user="root",
        check=True,
        timeout=60,
    )
```

**输入 → 成果：** `sb + workdir` → 沙箱用户、目录所有权和 Git 配置就位。辅助函数没有返回这些配置数据，成果体现在环境中。

## 4 启动辅助函数继续操作同一个沙箱

**执行逻辑：** 两个子类组好命令和环境后调用 `run_agent()`。它准备 `.harness` 目录，再交给长命令辅助函数。

| 函数 | 定义位置 | 调用位置 |
| --- | --- | --- |
| `run_agent()` | `slime/agent/harness/common.py:107` | `slime/agent/harness/claude_code.py:71`、`slime/agent/harness/codex.py:86` |
| `exec_and_wait()` | `slime/agent/sandbox.py:82` | `slime/agent/harness/common.py:111` |

`run_agent()` 的完整实现：

```python
async def run_agent(sb: Sandbox, *, workdir: str, start_cmd: str, env: dict[str, str], time_budget_sec: int) -> int:
    """Launch the agent (start_cmd) and run it to completion, returning its exit code."""
    meta_dir = f"{workdir}/.harness"
    await sb.exec(f"mkdir -p {meta_dir} && chown agent:agent {meta_dir}", user="root", check=True, timeout=30)
    exit_code, _ = await exec_and_wait(
        sb,
        cmd=start_cmd,
        user="agent",
        env=env,
        workdir=workdir,
        out_file=f"{meta_dir}/trajectory.jsonl",
        time_budget_sec=time_budget_sec,
        tag="run",
        want_output=False,
    )
    return exit_code
```

目录准备使用 `root`，CLI 启动与等待使用 `agent`。`workdir`、`start_cmd`、`env`、等待预算一同进入 `exec_and_wait()`。

## 6 进入具体的 E2B 命令实现

**执行逻辑：** `E2BSandbox.exec()` 把命令与选项交给 E2B SDK，并整理执行结果。

**函数名与定义位置：** `E2BSandbox.exec()`，`slime/agent/sandbox.py:309`。

以下为该函数的成功路径摘录：

```python
res = await self._rpc_retry(
    f"exec({cmd[:60]!r})",
    lambda: self._sb.commands.run(
        cmd,
        user=user,
        envs=env,
        timeout=timeout,
        on_stdout=lambda s: None,
        on_stderr=lambda s: None,
    ),
    idempotent=idempotent,
)
return res.exit_code, res.stdout or "", res.stderr or ""
```

| 调用输入 | 下层 SDK 参数或后续处理 |
| --- | --- |
| `cmd` | `commands.run()` 的命令参数 |
| `user` | `user=user` |
| `env` | `envs=env` |
| `timeout` | `timeout=timeout` |
| `idempotent` | 传给 `_rpc_retry()`，控制传输失败时是否允许重放 |
| `check` | SDK 抛 `CommandExitException` 时，决定抛出 `RuntimeError` 或返回退出结果 |

**实际 SDK 调用位置：** `slime/agent/sandbox.py:324`。这里到达执行环境的外部边界。`on_stdout` / `on_stderr` 回调不处理流片段，调用结束后仍从结果读取完整 stdout/stderr。

## 8 将环境操作放回动作 5

```text
Harness decides what to prepare and run
    -> Sandbox interface receives commands and file operations
    -> E2BSandbox translates them into SDK calls
    -> sandbox state changes; execution results return
```

动作 2 的主要交接成果是返回两份数据；动作 5 的成果还包括沙箱里的用户、配置、文件和运行进程发生变化。谁提供这个沙箱、失败时谁释放它，继续见[创建入口和生命周期](3.创建入口和生命周期.md)。
