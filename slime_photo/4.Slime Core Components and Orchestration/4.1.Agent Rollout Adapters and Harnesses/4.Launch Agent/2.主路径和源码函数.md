## 4 完整 `run()` 的调度骨架

真实 `run()` 的执行主体如下，按源码原样摘录：

```python
await _sandbox.ensure_agent_user(sb, workdir)
ctx = HarnessContext(
    workdir=workdir,
    session_id=session_id,
    adapter_url=adapter_url,
)
await self.write_config(sb, ctx)
return await self.launch_and_wait(sb, ctx, prompt, time_budget_sec)
```

这几步顺序执行。每步在 Harness 侧的目的与向环境的交接都要解释；下表标出深入位置。

| 入口中的位置 | 只需知道的职责 | 本章处理深度 |
| --- | --- | --- |
| `common.py:97`，`ensure_agent_user()` | 确认运行用户及目录权限 | Harness 发起准备；环境实现见动作 5 |
| `common.py:98`，`HarnessContext(...)` | 保留本次任务的运行上下文 | 展开字段与交接 |
| `common.py:103`，`self.write_config(sb, ctx)` | 准备配置内容并请求写入环境 | 本章展开子类；`sb.exec()` 接收端见动作 5 |
| `common.py:104`，`self.launch_and_wait(...)` | 构造命令与环境，委派运行并等待状态 | 本章展开准备与 runner；实际 CLI 执行见动作 6 |

上表 `common.py` 均为 `slime/agent/harness/common.py`。由于用户条件检查在上下文构造之前执行，源码中两者的顺序保留；本章只解释其中与交接相关的部分。

## 6 展开子类的启动准备

| 函数 | 定义位置 | 命令与环境准备 | 委派位置 |
| --- | --- | --- | --- |
| `ClaudeCodeHarness.launch_and_wait()` | `slime/agent/harness/claude_code.py:57` | `:58` 构造命令，`:62` 构造 `env` | `:71` 调用 `run_agent()` |
| `CodexHarness.launch_and_wait()` | `slime/agent/harness/codex.py:69` | `:71` 构造命令，`:75` 构造 `env` | `:86` 调用 `run_agent()` |

两种实现都以同一形式交给公共 runner：

```python
return await run_agent(sb, workdir=ctx.workdir, start_cmd=cmd, env=env, time_budget_sec=time_budget_sec)
```

附加参数可通过相应 `*_EXTRA_ARGS` 追加，额外环境变量可通过 `*_EXTRA_ENVS` JSON 最后合并。阅读运行配置时需要核对这些覆盖；本章示例使用空覆盖。

`run_agent()` 定义在 `slime/agent/harness/common.py:107`。它在 `:110` 准备 `.harness` 日志目录，在 `:111` 将命令、用户、环境、目录、输出路径和预算交给 `exec_and_wait()`。

## 7 用最短调用关系复述

```text
generate()
    → HARNESS_CLS().run(sb, workdir, session_id, adapter_url, budget, prompt)
    → BaseHarness.run() receives arguments
    → ensure_agent_user()
    → HarnessContext(workdir, session_id, adapter_url)
    → selected write_config() → sb operations
    → selected launch_and_wait() → cmd + env → run_agent()
    [action 5 follows sb operations]
    [action 6 follows CLI execution]
```

图里的 Core → Harness 在本地实现中通过外层 `generate()` 组织。没有额外的 `BaseAdapter._run_turn() → Harness.run()` 调用，也没有在这条交接边上传递动作 3 的 token 输出。
