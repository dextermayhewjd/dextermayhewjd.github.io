# 动作 4 启动参数、配置与启动信息

[返回入口](README.md) · [下一篇 主路径和源码函数](2.主路径和源码函数.md)

这一层观察启动参数进入 Harness 后，怎样变成配置与命令、环境变量。由 Sandbox 落实这些操作的机制在动作 5 展开；实际 CLI 执行与 HTTP 请求在动作 6、7 展开。

## 1 调用端已经知道什么

外层 `generate()` 准备本次任务的执行环境和启动信息，调用：

```python
agent_exit_code = await HARNESS_CLS().run(
    sb,
    workdir=md["workdir"],
    session_id=session_id,
    adapter_url=state.adapter_url,
    time_budget_sec=CONFIG.agent_time_budget_sec,
    prompt=swe.SWE_PROMPT,
)
```

| 参数 | 调用端来源 | 接收端用途 |
| --- | --- | --- |
| `sb` | `boot_agent_sandbox(md["image"], instance_id)` 创建，并调用所选 Harness 的 `install_cli()` | Harness 使用的执行环境 |
| `workdir` | `swe.get_metadata(base_sample, protocol)` 提取出的 `md["workdir"]` | 指定本次任务的工作目录 |
| `session_id` | `_session_id(base_sample, instance_id)` 复用或构造 ID，再调用 `adapter.open_session()` 注册会话 | 经 CLI 请求凭据连接同一会话 |
| `adapter_url` | `_AdapterService(args)` 启动 Adapter 服务，组合 `ADAPTER_PUBLIC_HOST` 与实际监听端口 | 告诉 CLI 向哪里请求模型 |
| `time_budget_sec` | `SweConfig.from_env()` 读取 `SWE_AGENT_TIME_BUDGET_SEC`，默认 `1800` | 限定运行等待预算 |
| `prompt` | `swe.SWE_PROMPT`，由 `SWE_CC_PROMPT` 或默认任务指令提供 | 告诉 CLI 读取问题文件并完成任务 |

`prepare_workspace()` 在调用 `run()` 前，把样本的具体题目写入 `workdir/PROBLEM_STATEMENT.md`。因此题目正文通过文件交付，`prompt` 提供读取与执行指令。

`sampling_params` 也在调用 `run()` 前通过 `adapter.open_session(..., sampling_defaults=sampling_params)` 保存，但没有作为 Harness 参数传递。后续 CLI 请求携带同一个会话标识，Adapter 才能取到对应的采样设置。

按实际执行顺序追踪这些来源，见[纵向数据流第 1–3 节](纵向数据流/README.md)。本章解释准备的用途与数据连接；沙箱创建、写文件等具体实现沿动作 5 深入。

## 2 接收端如何接住参数

`ClaudeCodeHarness` 和 `CodexHarness` 都继承 `BaseHarness.run()`。其签名为：

```python
async def run(
    self,
    sb: Sandbox,
    *,
    workdir: str,
    session_id: str,
    adapter_url: str,
    time_budget_sec: int,
    prompt: str,
) -> int:
```

`sb` 为位置参数，其他字段是关键字参数。调用端与接收端直接通过 Python 对象和函数参数交接，不需要额外的 HTTP 启动请求。

## 3 哪些字段进入上下文

`run()` 构造：

```python
ctx = HarnessContext(
    workdir=workdir,
    session_id=session_id,
    adapter_url=adapter_url,
)
```

用同一份教学数据得到：

```json
{
  "workdir": "/workspace/demo",
  "session_id": "cagent-demo-0-0",
  "adapter_url": "http://192.0.2.10:18001",
  "model_label": "slime-actor"
}
```

前三项原样保留，`model_label` 来自 `HarnessContext` 的默认值。**`prompt`、时间预算和 `sb` 没有被装进上下文**，它们继续以独立参数存在。

## 4 选择不同 Harness，交接契约怎样变化

| `SWE_AGENT` | 接收对象 | 公共接口 |
| --- | --- | --- |
| `claude_code`，默认 | `ClaudeCodeHarness` | 继承的 `BaseHarness.run()` |
| `codex` | `CodexHarness` | 继承的 `BaseHarness.run()` |

调用端交出的参数保持相同。不同接收对象在 `write_config()` 和 `launch_and_wait()` 中生成不同的配置和启动信息，下面继续展开。

## 5 `write_config()` 在 Harness 侧做什么

`run()` 调用 `self.write_config(sb, ctx)`，具体实现由子类决定。

| Harness | 准备的内容 | 交给 Sandbox 的操作 | 成果 |
| --- | --- | --- | --- |
| Claude Code | onboarding 与运行权限设置 JSON | `sb.exec()` 写 `.claude.json`、`.claude/settings.json`，调整所有权 | 配置文件就位 |
| Codex | 模型标签、provider 地址和协议的 TOML | 将 TOML 编码后交给 `sb.exec()` 写 `.codex/config.toml`，调整所有权 | 配置文件就位 |

配置路径位于 `/home/agent/`。这个函数返回 `None`，成果体现在环境中。**配置内容与操作需求由 Harness 决定；在环境中落实是动作 5 的接收端工作**。

## 6 `launch_and_wait()` 在 Harness 侧做什么

在真正启动之前，具体 Harness 先构造 `cmd` 和 `env`。

| 信息 | Claude Code | Codex |
| --- | --- | --- |
| 命令骨架 | `/usr/local/bin/claude -p ...` | `codex exec --skip-git-repo-check ...` |
| 指令 | `shlex.quote(prompt)` | `shlex.quote(prompt)` |
| 模型入口 | `ANTHROPIC_BASE_URL=ctx.adapter_url` | TOML provider 地址，以及 `OPENAI_BASE_URL=ctx.adapter_url + "/v1"` |
| 会话标识 | `ANTHROPIC_AUTH_TOKEN=ctx.session_id` | `OPENAI_API_KEY=ctx.session_id` |

随后调用公共 `run_agent(sb, workdir=..., start_cmd=cmd, env=env, time_budget_sec=...)`。它准备日志目录，将启动信息交给沙箱的长命令接口。**方法名包含 wait，但动作 4 在这里先读准备与委派部分**；CLI 执行和完成等待沿动作 6 继续。

## 7 返回值在本章怎样理解

接口声明 `run() -> int`；调用端把返回值保存为 `agent_exit_code`。由于调用使用 `await`，这个值要等 Harness 的运行工作结束后才会返回。

**阅读边界与函数运行时间是两件事**：本章读完 Harness 的调度与启动准备，并标出向 Sandbox 的交接。真实 `run()` 还会等待下游完成；这里只说明返回契约，不展开 CLI 执行中的循环、等待标记或评分。

完整边界捕获示例见[纵向交接数据](纵向数据流/README.md)。
