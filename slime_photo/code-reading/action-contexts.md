# 4.1：各章的阅读语境与源码入口

阅读一个 Action 时，先区分三件事：**现在跟随哪一层调用、这一章展开哪项职责、实现在哪些文件中。** 组件关系图用于定位；真实调用用于串起过程；文件列表用于打开源码。这三者不必一一对应。

## 当前采用的划分

- **Pre-4 与 4：一次样本任务的准备和启动。** 从 `examples/coding_agent_rl/generate.py::generate()` 跟随准备过程，再进入 `BaseHarness.run()`。Pre-4 准备输入；4 展开 Harness 怎样写配置、组织命令并等待 CLI。
- **5：可反复调用的环境能力。** 展开 `Sandbox` 接口及 `E2BSandbox` 的命令、文件和生命周期操作。准备工作区、启动 CLI、收集结果都可能用到它；读完回到具体调用处。
- **6：一次长命令的执行机制。** 从 `run_agent()` 进入 `exec_and_wait()`，看它如何组合 5 的能力，完成启动、等待和输出收集。5、6 都在 `sandbox.py` 中有实现，但阅读问题不同。
- **7：运行中的 CLI 如何发起模型请求。** 由 CLI 配置找到 Adapter 的 HTTP 路由和会话识别，然后进入 `_run_turn()`。CLI 内部管理历史、决定下一次工具调用的实现不在这份 Slime 源码中。
- **2 → 3 → 3.5：一次模型请求的内部处理。** 共同跟随 `BaseAdapter._run_turn()`：转换输入 → 编码与生成 → 解析回复、记录轨迹并返回。它们不是三个独立任务，也不是各读一整个文件。

`generate()` 是一次样本任务的异步编排入口，不是模型/工具循环本身。等待 `Harness.run()` 的期间，CLI 可以多次走过 7 → 2 → 3 → 3.5；实现分别留在 Harness、Adapter 和 Sandbox 等模块。外层任务随后继续收集补丁、评估和收尾。

因此，可以沿 `generate()` 追踪整个任务，但不能认为这些职责全都实现在 `generate.py` 中。相同文件在多章出现，也不等于需要每次通读。

## 每章共用的展示方式

局部图与阅读目标之后、调用骨架或逐步代码之前，保留一个简短的“本章阅读语境”块：

1. 当前主线：正在跟随的调用者或调用链。
2. 本章展开：本次下钻的问题与边界。
3. 读完返回：结果交给谁，在哪里继续。
4. 默认收起的“本章主要源码文件与入口”：相关文件的职责、符号、行号和固定源码链接。

文件清单只列支撑当前职责的入口，不列整个目录。详细源码证据继续放在解释附近的折叠块和各章 `SOURCE-CHECK.md`；用户不打开出处，也应能连续理解正文。
